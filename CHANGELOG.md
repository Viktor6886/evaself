# История изменений

## Не выпущено — непрерывность работы и версии Letta

### Добавлено

- **Непрерывность длительной работы.** Ева различает устойчивую цель
  многоходовой работы и цель текущего ответа, держит место остановки
  коротким чекпойнтом в `current_state` и не начинает процедуру заново.
  Временный переход к другому методу сохраняет исходную цель и точку
  возврата; явная пауза уважается, и возвращать к теме Ева сама не будет.
  Протокол живёт в `therapeutic_framework` и доезжает до существующих
  агентов той же синхронизацией персоны, что и сама рамка.
- **Курсор длинных guided-программ** — миграция `065_goal_program_runs`.
  Ключ и версия методики, фаза, шаг, пройденное и следующий шаг переживают
  перезапуск, новый conversation и сжатие истории. Курсор не дублирует
  «ВЕКТОР — Действие» и не хранит стенограмм, рассуждений и текста навыка:
  длину подсказки ограничивает сама схема. Один незакрытый запуск на
  человека и методику держит частичный уникальный индекс, поэтому повторный
  `start` возвращает сохранённое место, а не начинает методику заново.
- Инструменты `get_goal_program_context` и `update_goal_program`: владелец
  берётся из доверенного runtime, от устаревшей и повторной записи защищает
  `revision`, а повтор того же шага ревизию не двигает.
- `RuntimeContextBuilder` сообщает пять коротких фактов активной программы.
  Это факты, а не команда: приостановленная, завершённая и отменённая
  программа в ход не попадает вовсе.

### Изменено

- **Обновления Letta перестали быть ручной работой.** Связка версий жила в
  трёх местах, dependabot правил только одно, и его pull request приходил
  заведомо красным. Теперь версии выводятся из lock-файла
  (`scripts/ci/sync-letta-versions.py`), обязательная проверка CI не пускает
  рассинхрон, а `dependabot-letta-sync` дописывает недостающую половину
  прямо в pull request.
- Обновлены `bullmq` 6.2.0, `fastify` 5.12.1, `@types/pg` 8.23.1,
  `uvicorn` 0.52.4, NocoDB 2026.08.1, Uptime Kuma 2.5.3.

### Удалено

- **NocoDB убран из стека целиком** — сервис, профиль, домен, маршрут
  Caddy, том, база метаданных для новых установок, секреты `NC_*` и
  `NOCODB_DB_*`, скрипт синхронизации, цель `make nocodb-sync`, шаг CI и
  записи в каталоге сервисов. Продуктовый код от него не зависел: ни один
  сервис к нему не обращался, а разделы данных есть в административной
  панели. Обновление ничего не удаляет на существующей установке — база
  `nocodb`, роль, том и строки `.env` остаются нетронутыми; команды ручной
  очистки перечислены в `docs/UPDATING.md`.

### Известные ограничения

- **Agent SDK остаётся на 0.7.1.** Обновление до 0.7.3 проверено и
  отложено: статические проверки прошли полностью, но на живом стеке
  обычный ход уходит в подтверждение вместо ответа. `letta-code` 0.30.28
  добавил проверку разрешений с учётом аргументов вызова, а Ева работает в
  режиме `standard`. Разбор требует стенда с моделью.

### Документация

- `docs/IMPLEMENTATION_STATUS.md` переписан по фактической матрице: описание
  административного control plane через `letta-client` не соответствовало
  коду — пакет не является прямой зависимостью и нигде не импортируется.
- `docs/UPDATING.md` называет, что `make update` берёт из реестров образов,
  а что приходит из репозитория; версии Letta в опросе реестров не
  участвуют.

## Не выпущено — безопасность, надёжность и покрытие

Собрано поверх ветки `claude/evaself-telegram-deployment-ui10r6`, 34 коммита
которой не были слиты в `main` после PR №1.

### Исправлено

- Голосовые сообщения теперь сначала показывают Hermes-совместимую
  расшифровку `🎙️ "…"`, а затем ответ Евы; агент получает явный признак
  `message_source: voice`. Активный STT-провайдер заметен в панели, а
  реальный Telegram-поток записывает точные и общие секунды распознавания.

- **Cron больше не блокирует сервис.** `nextCronDate` перебирал минуты и
  создавал `Intl.DateTimeFormat` на каждой итерации: `0 0 1 1 *` занимало
  ~45 с, невозможное `0 0 30 2 *` — ~51 с и падало. Поиск идёт по дням с
  кэшированным форматтером (0.00 с), а выражение проверяется при создании
  задачи, а не в фоновом цикле.
- **`/public/bot` реализован.** Лендинг звал этот маршрут, а его не
  существовало. Он вынесен за пределы hook'а с проверкой initData: страница
  открывается вне Telegram и подписывать ей нечего.
- Лок пользователя продлевается, пока идёт ход: TTL (180 с) короче таймаута
  хода (240 с), и длинный ответ терял лок в середине.
- Admin API Caddy слушает `localhost:2019`, а не `0.0.0.0`.
- `/v1/*` закрыт на всех публичных хостах. Это `handle`, а не голый
  `respond`: Caddy сортирует `respond` после `handle`, поэтому очевидное
  написание было бы мёртвым кодом. Порядок закреплён проверкой в CI.
- `ACME_STAGING` действительно переключает CA: флаг был в `.env.example`, но
  `ACME_CA` не вычислялся.
- `doctor` читает активную LLM из реестра, а не из устаревшего `.env`.
- `update` распознаёт detached HEAD после `make rollback`.
- Мелкие дефекты, найденные линтером: неиспользуемая привязка в
  `auth-service`, конкатенация Buffer со строкой в updater, async-callback
  `server.listen`, ронявший отказ `chmod` в unhandled rejection.

### Добавлено

- Кризисный слой (`src/crisis.ts`): детерминированное распознавание риска,
  запись в `crisis_events` и уведомление владельца при `high`/`critical`.
  Таблица существовала с самого начала, но никто в неё не писал.
- Сегментация сетей `edge` / `data` / `agent` / `tools`; SearXNG и crawl4ai
  больше не видят PostgreSQL, Valkey, App Server и admin API Caddy.
- `media-service` требует `X-Media-Key`; открыт только `/health`.
- Копия бэкапа вне сервера (`BACKUP_UPLOAD_COMMAND`) и ротация по количеству
  архивов, а не только по возрасту.
- Content-Security-Policy для консоли, лендинга и Mini App; inline-скрипт
  лендинга вынесен в отдельный файл.
- ESLint (async-корректность) и ruff в CI.
- Проверка в CI, что каждый путь, который зовёт фронтенд, объявлен в сервисе
  — именно этот класс дефекта и был исходной причиной работы.
- Стековые проверки: `/public/bot` без initData, отказ media-service без
  секрета, изоляция SearXNG от слоя данных.
- Тесты: `payments.handle()` (путь начисления подписок был не покрыт вовсе),
  изоляция инструментов по `user_id`, продление лока, регрессия cron.
  Всего 129 → 160 тестов.

### Удалено

- Мёртвая схема `test_results`, `referrals`, `partner_analysis_links`,
  `notifications` (migration `016`, только если таблицы пусты) и метрика
  квоты `tests`, которую никто не увеличивал.
- Инструменты Todoist больше не регистрируются без токена: девять действий,
  падающих на первом вызове, только сбивают модель.

## Не выпущено — административная панель, фаза 1

### Добавлено

- отдельные `admin-ui` и `admin-api` на `/admin/`, без проксирования
  интерфейса Letta;
- migration `014_admin_panel_phase1.sql` и обратная миграция для
  администраторов, сессий, sudo, настроек, версий, Secret Store и аудита;
- Argon2id, server-side сессии, CSRF double submit, RBAC и 10-минутный
  scoped sudo;
- Secret Store AES-256-GCM с мастер-ключом в отдельном host-файле;
- декларативный реестр системных настроек, optimistic locking, rollback и
  событие `eva.config.changed`;
- одноразовый идемпотентный импорт существующей `.env`-конфигурации;
- CI-проверки утечки секретов, редакции логов, RBAC, sudo и полноты аудита.

### Изменено

- консоль agents, conversations и Agent SDK доступна только на домене
  Letta; корневой `/admin/` управляет общесистемными настройками и ключами;
- runtime читает зарегистрированные системные параметры из Config Service
  с приоритетом над bootstrap-окружением;
- установщик создаёт master key вне Docker volumes и не выводит
  административные пароли.

### Изменено

- Telegram сразу показывает пустой эфемерный черновик, затем раскрывает
  готовый ответ только целыми словами и сохраняет его одной финальной
  отправкой;
- streaming-порции Agent SDK объединяются без искусственных переносов строк,
  поэтому границы порций больше не разрывают слова;
- смена модели обновляет существующие agents и conversations через
  `@letta-ai/letta-agent-sdk`, не удаляя память;
- Letta App Server действительно перезапускается после изменения локального
  provider store; при неудаче остаётся активной предыдущая конфигурация;
- backup/restore включает реестр LLM, ключ шифрования и provider volume;
- Node-образы переведены с Alpine на Debian Bookworm Slim для нативной
  сборки `node-pty`;
- migration 002 стала идемпотентной после изменения представления migration
  003; CI применяет весь набор миграций три раза;
- архитектурная проверка Agent SDK больше не принимает собственные маршруты
  Evaself за самописный Letta REST client;
- пользовательские и административные материалы переведены на русский;
- из стека удалены установка стороннего host-агента, его systemd unit,
  команды, вопросы установщика и интеграция с backup/restore/doctor.
- оркестратор автоматизации и его worker/runner полностью удалены; бизнес-
  логика выполняется кодом в `eva-agent-service`;
- исправлены чистая инициализация PostgreSQL через Unix socket, безопасная
  загрузка bcrypt из `.env`, JSON default мастера и вывод CLI LLM.

## 0.1.0 — первоначальный стек

Первый self-hosted стек с PostgreSQL, Valkey, Caddy, NocoDB, WebApp,
Media Service, SearXNG, backup, restore, update и rollback.
