## Текущая порция: жизненный цикл подписки и read-only статус

Повторная покупка действующего тарифа и понижение блокируются до списания,
одновременно возможен только один Stars checkout. Повышение Plus → Max
сохраняет оплаченный остаток: срок складывается, периодические квоты
взвешиваются по оставшимся и новым дням, total-квоты суммируются. Фактические
лимиты конкретной подписки хранит миграция `074_subscription_lifecycle`.

Ева получила один серверный read-only инструмент без аргумента пользователя:
тариф, срок, оставшиеся дни, текущие квоты и бесплатные сообщения. Отдельный
детерминированный сервис без LLM ставит в durable outbox предупреждение за
24 часа до конца, один раз для каждой пары «подписка + срок».

Проверки: targeted payment/subscription tests, build, lint, typecheck,
tenant-scope и полный набор тестов сервиса. Pull request
[#295](https://github.com/Viktor6886/evaself/pull/295) открыт, CI и независимое
ревью ожидаются.

Независимое ревью указало на fail-safe квот, пагинацию уведомлений и
отсутствовавший rollout-флаг. Исправления добавлены; новый жизненный цикл
включается `EVA_SUBSCRIPTION_LIFECYCLE=false → true` после canary.
Повторное ревью дополнительно выявило смешивание конечной квоты с безлимитом
и риск отправки предупреждения в групповой чат: безлимит теперь включается
после старого срока, а уведомление всегда адресуется личному Telegram ID.
Финальное ревью добавило случай повторного Lava-платежа: уже купленная дата
начала безлимита сохраняется и не отодвигается новым начислением.
Также подтверждение Lava теперь сообщает фактически сохранённый fail-safe
тариф, а не тариф из устаревшей ссылки оплаты.
Бессрочный доступ защищён отдельно: ограниченная покупка не переносит
бессрочность на новый, более высокий тариф, в том числе при rollback-флаге.

## Предыдущая порция: надёжная активация подписки после оплаты звёздами

Telegram подтверждал списание, но ошибка `stars.apply()` проглатывалась в
workflow. Durable update после этого получал ложный `completed`, поэтому ни
подписка, ни повторная попытка не появлялись. Платёж вынесен перед Letta и
прочими зависимостями диалога, ошибки применения теперь доходят до retry
inbox. При старте старые успешные платежи без записи в `payments`
возвращаются в очередь; повтор безопасен по `telegram_payment_charge_id`.

Проверки: build, lint, typecheck, tenant-scope и полный набор тестов сервиса.
Pull request [#293](https://github.com/Viktor6886/evaself/pull/293): все
обязательные проверки зелёные, независимое Codex-ревью без замечаний, смержен.

## Предыдущая порция: единая административная панель

Административная часть сведена в одну панель на `https://<домен>/admin`.
Публичных имён осталось три: корневой домен, `app.` и `api.` Консоль Letta
и страница статуса стали разделами панели, их поддомены отвечают только
308-редиректом, а сервисы `letta-ui` и `uptime-kuma` выведены из
эксплуатации.

Новое в панели: агенты (через production-путь Letta Agent SDK), подписки
(ручное решение отличимо от оплаты), персона и системный промпт (правка
настоящих production-источников с немедленным применением), Letta и
мониторинг.

Миграция `067_admin_panel_unification`. Проверки:
`scripts/ci/assert-single-admin-domain.py` и
`scripts/ci/test-admin-routing.sh`.

Pull request #268, обязательные проверки зелёные (прогон 648). Мерж ждёт
независимого ревью: протокол его требует, а в сессии реализации его
выполнить нельзя — автор изменения не оценивает собственную готовность.

Значения полей:

- `BASELINE` — коммит `main`, от которого отсчитывается текущее состояние.
- `BRANCH` — рабочая ветка текущей порции, `—` пока работа не начата.
- `STATUS` — `нет активной работы` · `в работе` · `на ревью` · `заблокирован` ·
  `выполнен`.
- `LAST_COMMIT` — последний checkpoint-коммит в `BRANCH`. Точка возобновления
  после обрыва сессии: код берётся отсюда, а не из памяти сессии.
- `BLOCKER` — причина остановки либо `—`. Непустое значение запрещает продолжать.
- `NEXT` — одно конкретное следующее действие, а не план.

Блок обновляется до пуша: если сессия оборвётся, следующий агент восстанавливает
работу из Git и этого блока.

## Точка отсчёта

Архитектура приведена к Letta-native: Letta Agent SDK и App Server —
единственный когнитивный runtime, Evaself — продукт вокруг него. Самописный
cognitive middleware удалён целиком (PR #188). Граница ответственности —
`CLAUDE.md`, раздел «Главная граница», и `docs/letta-native.md`.

Что это значит для планирования: **прежний roadmap по шагам 27–67 больше не
является обязательной работой.** Он строился вокруг подсистем, которых в
репозитории нет — графовой и temporal памяти, Memory Curator, Hybrid
Retrieval, SkillRouter, ToolGateway. Возобновлять его как есть нельзя: это
означало бы восстановить удалённый cognitive middleware в обход инварианта 3.

Архив прежнего roadmap со статусами выполненных batch — `docs/ROADMAP_ARCHIVE.md`.
Он читается только как история: что уже сделано и зачем. Заданием он не является.

## Что вошло в базовую точку

Восемь шагов приёмки поверх `f104d90`, по одному коммиту на шаг:
источник истины архитектуры (1), разрешения, публичный SDK и приватность
трассы (2), роутер без семантической классификации (3), контекст хода без
prompt middleware (4), готовность по фактам runtime и smoke памяти (5),
capability probe модели (6), необязательная инфраструктура вне обязательного
пути (7), финальная приёмка: сверка ссылок, мёртвый код, документация (8).

Поверх них — доработки по результатам аудита и первого прогона CI: путь
исследования (conversation открывает сервер, отказы получили устойчивый
JSON-контракт), готовность со сроком годности и состоянием
`ready`/`degraded`/`not_ready`, кризисное событие без прямой речи,
отдельный ключ шифрования конфигураций, потолок и метрики служебного
блока, живой smoke отдельным workflow. Красные проверки CI разобраны по
первопричинам: клиент PostgreSQL по версии сервера, fail-closed сравнение
схем, смысловые инварианты вместо числа строк, порядок проверки
готовности.

## Как берётся следующая работа

Работу задаёт человек. Порция работы = одна ветка, один pull request, один
прогон CI, одно ревью — протокол в `CLAUDE.md`, раздел «Batch-протокол».

Прежде чем взять задание из `prompts/step-NN-*.md`, сверь его с разделом
«Главная граница» в `CLAUDE.md`. Шаг, который строит собственную память,
собственное извлечение, свой роутер навыков или подходов, свой compaction или
свою ротацию conversation, выполнять нельзя — сначала это обсуждается с
человеком.

Шаг получает статус `выполнен` только внутри смерженной порции. Порция получает
статус `выполнен` только после зелёных обязательных проверок на pull request,
независимого ревью и мержа.

Красная проверка, упавший тест и недоступный перезапуск job статус
`заблокирован` не дают: они чинятся по разделу «Красная проверка» в
`CLAUDE.md`. `заблокирован` ставится только при неустранимой внешней
зависимости — раздел «Остановка» там же.
