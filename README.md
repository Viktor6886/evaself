# Evaself

**Ева — ИИ-компаньон для саморефлексии, который живёт на вашем сервере.**
Telegram-бот, Mini App и административная панель поверх self-hosted
когнитивного runtime. Ничьи разговоры не уходят в чужое облако: память,
история и модель — там, где вы их поставили.

```bash
git clone https://github.com/Viktor6886/evaself.git
cd evaself
sudo make install
```

Чистая Ubuntu 24.04, один корневой домен, десять минут. Telegram-бот и
LLM-провайдер можно подключить позже — установка не заблокируется без них.

---

## Главная идея

У большинства «AI-ассистентов» память — это своя таблица с эмбеддингами и
свой поиск по ней. Evaself устроена иначе, и это её единственное
архитектурное решение, из которого следует всё остальное:

> **Letta Agent SDK и App Server — единственный когнитивный runtime Евы.
> Evaself — продукт вокруг него.**

| Letta решает | Evaself решает |
|---|---|
| что вспомнить и когда | кто этот человек и что ему доступно |
| чем ответить и каким инструментом | доставку, повторы, идемпотентность |
| когда сжать контекст | цели, задачи, напоминания, дневник |
| memory blocks, MemFS, навыки | подписки, платежи, квоты |
| рефлексию между ходами | границы безопасности и аудит |

Между человеком и Letta нет второго «умного» слоя, который решал бы за
модель, что ей вспомнить. Нет своего MemoryManager, своего RAG-контура,
своего роутера навыков. Такой слой легко написать и невозможно отладить:
когда ответ получился плохим, непонятно, кто виноват — модель или
самодельная обвязка вокруг неё.

Что из этого следует на практике — [docs/letta-native.md](docs/letta-native.md).

## Поток сообщения

```text
Telegram webhook
  └─ PostgreSQL telegram_updates      быстрый ответ Telegram, ничего не теряется
       └─ inbox dispatcher            один человек последовательно, разные — параллельно
            └─ RuntimeContextBuilder  время, часовой пояс, подписка, состояние целей
                 └─ Letta Agent SDK → App Server (WebSocket)
                      └─ LLM Router → цепочка провайдеров с failover
                           └─ PostgreSQL telegram_outbox
                                └─ delivery worker → Telegram
```

Ответ фиксируется в outbox **до** отправки. Сбой доставки повторяет только
отправку и не запускает второй ход модели — человек не получит два разных
ответа на одно сообщение. Пока Ева думает, в Telegram виден растущий
черновик, а не молчание.

## Что внутри

**Память.** Четыре memory block — `persona`, `human`, `current_state`,
`therapeutic_framework` — всегда в контексте. Подробности Ева ведёт сама в
MemFS нативными инструментами. PostgreSQL хранит связь
`человек → агент → диалог`, но переписку не зеркалирует.

**Непрерывность.** Психологический разбор живёт дольше одной реплики. Ева
различает устойчивую цель работы и цель текущего ответа, а место остановки
держит чекпойнтом в `current_state`. Бытовой вопрос посреди разбора его не
закрывает; явное «не хочу» — закрывает, и возвращать к теме Ева сама не
станет.

**Цели.** «ВЕКТОР — Действие»: направления, подтверждённые цели, рабочие
блоки, обзоры. Это продуктовые данные в PostgreSQL, доступные Еве через
типизированные инструменты. Модель не пишет SQL — она вызывает инструмент,
а запись делает серверный код с проверкой владельца и идемпотентностью.

**Профиль.** Дополняется без анкеты: не больше одной уместной подсказки за
ход, с cooldown и уважением отказа. Город превращается в IANA timezone,
локальное время задач — в UTC с учётом переходов.

**Mini App.** «Сегодня», «Цели», «Прогресс», «Профиль» — ближайший шаг,
запуск и завершение рабочего блока, подтверждение сведений о себе. Каждый
запрос подписан Telegram `initData`; `user_id` из тела запроса не
доверяется никогда.

**Голос и медиа.** Распознавание речи с цепочкой провайдеров и ротацией
ключей, синтез речи, разбор вложений и документов, приватный поиск через
SearXNG, чтение веб-страниц через Crawl4AI.

## Административная панель

Один адрес на всю установку: **`https://<домен>/admin`**. Одна сессия, одни
роли, один журнал. Отдельных консолей со своими паролями нет.

<table>
<tr><td><b>Люди</b></td><td>пользователи · подписки</td></tr>
<tr><td><b>Ева</b></td><td>агенты · персона и промпт · Letta</td></tr>
<tr><td><b>Модели и медиа</b></td><td>ИИ · распознавание речи · синтез речи · распознавание медиа</td></tr>
<tr><td><b>Система</b></td><td>мониторинг · сервисы · backup и обновления · настройки · ключи · журнал</td></tr>
</table>

Разделы — настоящие адреса: `/admin/agents`, `/admin/letta`,
`/admin/monitoring` можно дать ссылкой и открыть заново.

Панель рассчитана на телефон всерьёз, а не «тоже открывается»: посмотреть,
отвечает ли Ева, и переключить провайдера — это делают в дороге. Таблицы
становятся карточками, диалоги приходят снизу, а канонический текст правится
на весь экран.

Три раздела стоит назвать отдельно.

**Агенты.** Один человек — один агент. Создание идёт **тем же путём Letta
Agent SDK**, каким агент заводится при первом сообщении в Telegram: второго
механизма создания агентов в системе не существует. Изменение пишется
сначала в Letta и только потом в зеркало `agent_links` — чтобы никогда не
получилось «в базе одно, в Letta другое». Удаление необратимо, требует ввода
`agent_id` и отклоняется, пока человек ждёт ответа.

**Персона и промпт.** Правятся настоящие production-источники личности Евы.
Файлы репозитория (`library/persona/eva.md`,
`library/system/letta_local_memfs.md`) остаются значением по умолчанию, а
правка становится версией в реестре артефактов — с историей, откатом и
возвратом к файлу. Сохранение **применяется сразу**: новый агент создаётся с
новым текстом, существующие приводятся к нему тем же `PersonaSync`, а панель
показывает, сколько агентов уже на текущей версии и сколько отстало.
Состояния «сохранено, но не действует» в панели нет — оно выглядит успешным
и работает по-старому.

**Подписки.** Платёж и право доступа — разные сущности. Ручное решение
администратора отличимо от оплаты, и снятие ручного решения возвращает
человека к оплаченному доступу, не задевая его. Отобрать оплаченный доступ
можно только отменой — это другое действие, с подтверждением.

Безопасность панели: server-side сессии на Argon2id, CSRF, роли, права
сессии на привилегированные действия и запись в аудит каждой мутации.
Пароль вводится один раз — при входе; дальше действия с последствиями
подтверждаются окном, которое называет последствие, а необратимые — ещё и
контрольным словом. Десять неверных паролей подряд — минута блокировки,
и каждая следующая ошибка снова минута, пока не пройдут сутки без ошибок.
Переписка требует подтверждения и пишет собственную запись — кто и чей
диалог открыл, без текста. Значения секретов браузеру не возвращаются
никогда. Перезапуск сервисов выполняет отдельный `eva-updater` с узким
списком команд; у `admin-api` нет доступа к Docker socket.

## Модели

Evaself не привязана к одному провайдеру. Конфигурации живут в PostgreSQL,
API-ключ зашифрован AES-256-GCM и обратно в браузер не приходит.

Два режима: `adaptive` держит независимые цепочки для ролей `chat`, `deep`,
`fast`, `json` с автоматическим failover, `single` направляет всё одному
провайдеру. Переключение не пересоздаёт агентов и не стирает цепочки.

Перед активацией модель проходит проверку возможностей: ответ, вызов
инструмента и приём его результата обязательны, а поток, изображения и
строгий JSON — необязательны и закрывают лишь соответствующие маршруты.
Модель, которая не умеет вызывать инструменты, не станет основной молча.

```bash
make configure-llm   # добавить, проверить и активировать
make test-llm        # проверить активного провайдера
make list-models     # запросить /models
```

## Эксплуатация

```bash
sudo make install                  # установка на чистый сервер
make doctor                        # полная проверка: контейнеры, HTTPS, база, агенты
make status                        # что запущено
make logs s=eva-agent-service      # логи одного сервиса

make backup                        # зашифрованный архив
make restore BACKUP=/path/archive.tar.gz
make update-preview                # что изменится, ничего не трогая
make update                        # backup, обновление, проверка, автооткат
make rollback                      # вернуться к предыдущим версиям

make validate                      # статические проверки compose/Caddy/SQL
make test                          # тесты сервисов
```

`make update` закрывает весь цикл сам: снимает backup, прячет локальные
правки в stash, возвращается на релизную ветку, накатывает миграции,
пересоздаёт контейнеры и запускает `doctor` — а при его провале
откатывается.

Команды, удаляющей volumes, намеренно нет: ошибочная команда не должна
стереть память и настройки.

## Требования

- Ubuntu 24.04 x86_64, root/sudo;
- три A-записи на IP сервера: корневой домен, `app.` и `api.`;
- открытые 80/tcp, 443/tcp, 443/udp;
- 4 ГБ RAM минимум, 8 ГБ рекомендуется;
- доступ к Docker Hub, GitHub, npm и выбранному LLM-провайдеру.

Наружу опубликованы ровно эти три имени. PostgreSQL, Valkey, Letta App
Server, внутренний API сервиса, SearXNG и media-service остаются во
внутренних сетях и недоступны из интернета.

## Границы

Ева — эмпатичный компаньон и ассистент по самопознанию. Она **не**
лицензированный психолог, врач или психотерапевт, и говорит об этом прямо.
Она не ставит диагнозов, не назначает лечение и не отменяет назначения
врача. Кризисный контур детерминированный, приоритетный и неблокирующий —
он не зависит от того, что решит модель.

Сырые рассуждения модели не сохраняются, не трассируются и не показываются.
Содержимое диалогов не уходит в телеметрию.
