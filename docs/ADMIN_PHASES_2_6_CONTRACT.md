# Административная панель: контракт фаз 2–4 и 6

Документ фиксирует контракт до реализации интерфейса. Управление агентами,
conversation и памятью остаётся только в Letta. Административная панель
Evaself управляет состоянием установки, интеграциями, провайдерами и
эксплуатационными операциями.

## Фаза 2 — обзор, сервисы и интеграции

- `health-worker` раз в 60 секунд обновляет `service_statuses`.
- `GET /api/admin/v1/overview` читает только PostgreSQL и не выполняет
  исходящих запросов.
- Ручная проверка создаёт строку `health_checks` и отвечает `202`.
- Результат доступен через `GET /checks/{id}` и события SSE.
- Цвет вычисляется единственной функцией: `gray`, `blue`, `red`, `yellow`,
  `green`.
- Перезапуск выполняет только `eva-updater` через Unix socket. `admin-api`
  Docker socket не получает.

Фоновые задания: периодическая проверка снимков, обработка ручных проверок,
очистка старых проверок и публикация изменений статуса.

## Фаза 3 — искусственный интеллект

- Браузер работает только с защищённым административным API.
- LLM-операции административный API передаёт существующему runtime, который
  сохраняет агентов, conversation и память при переключении модели.
- API Key остаётся write-only.
- Адрес провайдера до сохранения проверяется `OutboundGateway`.
- Каталог Letta содержит только `provider_id`, `model_id`, `display_name` и
  `context_window`.
- Embeddings включаются только после подключения runtime-адаптера. Изменение
  размерности при наличии данных блокируется.

Фоновые задания: обновление каталога моделей, проверка провайдеров, снятие
cooldown ключей.

## Фаза 4 — интеграции

Единый реестр содержит Telegram, Google AI, ASR, TTS, Todoist, SearXNG,
Crawl4AI и monitoring. В JSON-конфигурациях разрешены только ссылки
`secret_ref`; сами значения находятся в Secret Store.

Фоновые задания: проверки интеграций, Telegram inbox/outbox, контроль
cooldown проектных групп Google и удаление временных медиафайлов.

## Фаза 6 — backup, обновления и перезапуск

- `eva-updater` принимает только команды из фиксированного списка по Unix
  socket и единственный имеет Docker socket.
- Любая операция создаётся в `admin_operations` и выполняется асинхронно.
- Backup и обновление принимают `Idempotency-Key`.
- Перед обновлением обязателен backup; при неуспехе запускается rollback.
- Restore, update и rollback требуют owner, sudo и явного подтверждения
  последствия.

Фоновые задания: выполнение очереди операций, синхронизация списка архивов,
проверка checksum, проверка обновлений и retention backup.

## Общие ограничения

- Секреты не возвращаются в API, HTML, JavaScript, логи или аудит.
- Все административные мутации имеют `pending`, затем `success` либо
  `failure` в аудите.
- Пользовательские URL проходят DNS/IP-проверку, повторную проверку каждого
  redirect, лимиты времени и размера ответа.
- Отказ внешней интеграции не останавливает Evaself.
