# Статус реализации интерфейсов

Evaself разговаривает с Letta через `@letta-ai/letta-agent-sdk` **0.7.1** —
это единственный conversational и когнитивный runtime (инвариант 3).

Второго клиента у приложения нет. `@letta-ai/letta-client` не является
прямой зависимостью `eva-agent-service` и не импортируется в его коде: он
приходит транзитивно вместе с SDK и приложением не используется. Так
устроено намеренно (инвариант 4): против self-hosted App Server работает
только Agent SDK по WebSocket, а операция, которой в нём нет, остаётся
неподдержанной, а не подменяется вторым путём.

Версия закреплена точно, без диапазона; `@latest` для SDK, CLI и GitHub
Actions запрещён. Связка версий SDK, CLI образа App Server и клиента
выводится из lock-файла и раскладывается по файлам скриптом
`scripts/ci/sync-letta-versions.py` — подробности в
[letta-native.md](letta-native.md).

Матрица ниже — не список намерений. Каждая поддержанная строка проверяется
contract-тестом `test/letta-contract.test.ts`: он ищет метод на живом
объекте установленного пакета, а не сверяет типы. Источник матрицы —
`eva-agent-service/src/letta/capabilities.ts`; расхождение реестра с
установленной версией красит прогон.

## Поддержано Agent SDK

Управляющие операции — семнадцать путей:

| Операция | Что делает |
|---|---|
| `agent.create` · `agent.list` · `agent.retrieve` · `agent.update` · `agent.delete` | жизненный цикл агента |
| `conversation.create` · `conversation.list` · `conversation.retrieve` · `conversation.update` | жизненный цикл conversation |
| `conversation.archive` | архивирование полем `archived` обновления |
| `conversation.messages` | история сообщений conversation |
| `conversation.purpose` | conversation по назначению, включая research |
| `session.resume` | открытие и возобновление сессии |
| `models.list` | каталог моделей |
| `skills.sources` | источники навыков |
| `session.memfs` | MemFS агента |
| `session.dreaming` | рефлексия (dreaming) |

Операции сессии — семь путей:

| Операция | Что делает |
|---|---|
| `turn.send` · `turn.stream` · `turn.abort` | отправка, стриминг и отмена хода |
| `session.bootstrap` | восстановление состояния сессии после перезапуска |
| `approvals.recover` | восстановление ожидающих approvals |
| `session.messages` | история сообщений сессии |
| `session.status` | состояние устройства сессии |

## Не поддержано

Девятнадцать операций реестра не поддержаны ни одним доступным путём. Среди
них — удаление conversation (в Agent SDK его нет вовсе, только
архивирование), CRUD существующих memory blocks, каталог и attach/detach
инструментов, режим подтверждения инструмента, список MCP-серверов и
knowledge folders, экспорт и импорт агента, managed groups, экспорт в
архив.

Это не «пока не сделали». Каждая такая запись остаётся в реестре с
`surface: null` и объяснённой причиной, а вызов падает кодом
`unsupported_operation` (HTTP 501) и не повторяется. Имитировать их
прямыми HTTP-запросами к App Server или вторым клиентом запрещено:
поддержка приходит обновлением пакета, а не обходным путём.

Практическое следствие для раздела «Letta» административной панели:
состояние memory blocks, инструментов, MCP и knowledge folders он
показывает по фактам, которые отдаёт сессия, и не редактирует их. Персона и терапевтическая
рамка обновляются не блочным CRUD, а проекцией в MemFS —
`updateAgentPersona` пишет `system/persona.md` и
`system/therapeutic_framework.md` и коммитит их в git-репозиторий MemFS.

## Что проверяет contract-тест

- каждый управляющий путь есть на живом клиенте Agent SDK;
- каждый путь сессии есть на живой сессии;
- удаления conversation в Agent SDK нет, а архивирование — поле обновления;
- операция, непроверяемая методом, обязана объяснить, почему;
- неподдержанная операция видна как неподдержанная, а не как успех;
- поддержанная операция проходит проверку и не бросает;
- матрица называет версию для каждой поддержанной операции;
- установленная версия совпадает с проверенной, а SDK закреплён точно.

Чего тест не проверяет и не притворяется, что проверяет: поведение
операции на работающем App Server. Для этого нужен живой стенд, и он
остаётся за smoke-прогонами (`scripts/smoke-eva-memory.mjs`,
`scripts/smoke-eva-restart.mjs`) и за job `Stack smoke test` в CI.
