# OSINT: исследование открытых источников

Ева умеет исследовать открытые источники по людям, аккаунтам, организациям,
телефонам, почте, доменам, IP-адресам, ASN, публичным документам и
официальным реестрам. Этот документ — архитектура контура, его границы и
порядок ввода.

Статус: **фундамент (batch OSINT-1)**. Есть доменный слой и схема
PostgreSQL. Сборщиков, инструментов Letta и заданий ещё нет, и контур пока
ничего не делает для пользователя. Порядок дальнейших batch — в конце
документа.

## Главная граница

Letta остаётся единственным когнитивным runtime Евы. OSINT — не второй
агент, а набор детерминированных компонентов, которыми Ева управляет через
несколько высокоуровневых инструментов:

| Решает Ева (Letta) | Решает код OSINT-контура |
|---|---|
| когда начать исследование и что спросить у человека | нормализацию идентификаторов |
| как объяснить отчёт человеку | выбор сборщиков и порядок их запуска |
| предложить план поиска и кандидатов на совпадение | проверку и урезание плана по бюджету |
| | тождество сущностей по признакам и порогам |
| | уверенность утверждений и их статус |
| | поиск противоречий |

Модель может предложить, что две записи описывают одного человека, но
объединяет их только детерминированный код (`src/osint/resolver.ts`) по
признакам с доказательствами. Совпадения имени для этого недостаточно
никогда.

Данные OSINT — о третьих лицах, а не память Евы. Они живут в таблицах
`osint_*` и не попадают в memory blocks Letta (`human`, `persona`,
`current_state`, `therapeutic_framework`). Evaself их туда не пишет.

## Кому доступно и на каких условиях

Решение владельца (2026-09-25): исследование людей доступно всем
пользователям. Это исключение из инварианта 30 корневого `CLAUDE.md`
(«скрытый анализ третьего лица запрещён»), и оно действует только на
следующих условиях:

- исследование начинается только по явной просьбе человека, не по
  инициативе Евы;
- у исследования есть заявленная цель (`osint_investigations.purpose`,
  `NOT NULL`): без неё запись не создаётся;
- у каждого пользователя лимит исследований и бюджет каждого из них;
- создание, просмотр и удаление исследования пишутся в аудит;
- контур выключен флагом по умолчанию и включается человеком.

Запрещено независимо от флагов:

- утёкшие базы, дампы учётных данных, украденные базы, боты «пробива»,
  базы операторов связи и банков, закрытые государственные базы;
- обход авторизации и CAPTCHA, подбор паролей, взлом аккаунтов;
- распознавание лиц для идентификации человека;
- отслеживание точного физического местонахождения человека;
- связь человека с IP-адресом без публичного источника, прямо её
  утверждающего;
- проверка существования аккаунтов перебором (Holehe и подобные) в
  обычном режиме.

## Модель данных

### Идентификатор и сущность — разные вещи

`ivan@example.com` — идентификатор: строка, которую можно нормализовать и
искать. Человек, которому адрес принадлежит, — сущность. Связь между ними
(`osint_entity_identifiers`) сама требует доказательства, источника и
уверенности.

Виды идентификаторов (`src/osint/types.ts`): `name`, `username`, `email`,
`phone`, `url`, `domain`, `ip`, `cidr`, `asn`, `organization`, `tax_id`,
`registration_number`, `social_account`, `document`.

### FollowTheMoney

Семантика сущностей и связей — FollowTheMoney 4.11.0 (MIT, OpenSanctions),
чтобы граф выгружался в Aleph, yente и nomenklatura без перевода:

- сущности: `Person`, `Organization`, `Company`, `LegalEntity`,
  `PublicBody`, `UserAccount`, `Address`, `Document`;
- связи: `Ownership`, `Directorship`, `Membership`, `Employment`, `Family`,
  `Associate`, `Representation`, `UnknownLink`;
- свойства утверждений — имена свойств FtM: `birthDate`, `innCode`,
  `ogrnCode`, `email`, `phone`, `username`.

Где FtM не покрывает задачу, модель расширена, и расширение видно по
имени:

- **инфраструктура** — `eva:Website`, `eva:Domain`, `eva:IPAddress`,
  `eva:Network`. В FtM 4.11.0 домен, IP и ASN — значения свойств, а не
  сущности (проверено по списку схем пакета);
- **почта и телефон остаются идентификаторами**, а не сущностями
  `Email`/`PhoneNumber`. В FtM схема `Email` — это письмо, а не адрес, и
  назвать так адрес значило бы сломать совместимость, ради которой FtM
  выбран.

FollowTheMoney и nomenklatura — библиотеки Python, а `eva-agent-service`
написан на TypeScript. Поэтому они работают в `osint-worker` (batch
OSINT-2). В TypeScript хранится совместимая схема и политика решений.

### Таблицы (`postgres/migrations/084_osint_foundation.sql`)

| Таблица | Что хранит |
|---|---|
| `osint_investigations` | запрос, цель, режим, статус, бюджет, ключ идемпотентности |
| `osint_entities` | сущность пользователя: схема и подпись |
| `osint_investigation_entities` | какие исследования используют сущность |
| `osint_identifiers` | нормализованные идентификаторы, уникальные у пользователя |
| `osint_entity_identifiers` | связь сущности с идентификатором — с доказательством |
| `osint_sources` | источник: адрес или локатор API, сборщик, уровень, качество |
| `osint_evidence` | цитата или структурированный фрагмент и его отпечаток |
| `osint_claims` | утверждение о свойстве сущности со статусом и уверенностью |
| `osint_relationships` | связь между сущностями по схеме FtM |
| `osint_entity_matches` | решение о тождестве: статус, счёт, признаки |
| `osint_collector_runs` | прогон сборщика и его исход, включая деградацию |
| `osint_frontier` | очередь итеративного расширения с глубиной |

Граница арендатора держится в самой схеме. В каждой таблице есть
`user_id NOT NULL`, и каждая ссылка между таблицами идёт по паре
`(id, user_id)`: утверждение одного пользователя не может сослаться на
сущность или доказательство другого, даже по известному UUID. Это
проверяет `scripts/ci/test-osint-schema.sql` на настоящем PostgreSQL. Все
таблицы внесены в реестр `src/tenancy/tables.ts`.

Удаление исследования каскадно уносит его источники, доказательства,
утверждения, связи и прогоны. Сущности пользователя остаются: их могут
использовать другие его исследования. Сущности, которые не использует ни
одно исследование, будет чистить сервис хранения (batch OSINT-3).

## Доказательства и уверенность

Ни одно утверждение не становится фактом только потому, что так сказал
сборщик или модель. У каждого утверждения есть сущность, свойство и
значение, источник (адрес или локатор, сборщик, время), доказательство и
его отпечаток SHA-256, уверенность и статус.

Доказательство (`src/osint/evidence.ts`) бывает двух видов:

- **цитата** — обязана буквально входить в текст источника. Проверка та
  же, что в `ResearchOrchestrator`: цитата, которой нет в тексте, — догадка
  модели;
- **структурированный фрагмент** ответа API. Отпечаток считается по
  каноническому JSON, и порядок ключей его не меняет.

Уверенность (`src/osint/confidence.ts`) считает код:

- у источника есть уровень, от официального реестра (0.95) до
  неизвестного сайта (0.2);
- независимыми считаются только разные домены: перепечатка одной статьи
  двадцатью агрегаторами — одно свидетельство;
- «подтверждено» требует первичного источника: официального реестра,
  сайта, профиля или первичного документа;
- слабые источники в любом количестве не поднимаются выше потолка своего
  уровня;
- противоречие перекрывает любую уверенность.

## Тождество сущностей

`src/osint/resolver.ts` выносит решение `confirmed`, `probable`,
`possible`, `conflicting` или `rejected` по признакам. Каждый признак
обязан ссылаться на доказательства; признак без доказательства в решение
не входит.

| Признаки | Вес |
|---|---|
| одинаковый ИНН или ОГРН | тождество |
| профили ссылаются друг на друга | 0.9 |
| один профиль ссылается на другой | 0.6 |
| общий подтверждённый e-mail или телефон | 0.7 |
| общий публичный сайт | 0.5 |
| одинаковая дата рождения | 0.3 |
| точное совпадение username | 0.25 |
| имя, город, работодатель, должность, биография, общие связи | 0.05–0.15 |

Признаки против:

- **жёсткие** — разный ИНН или ОГРН, разная дата рождения, несовместимый
  возраст;
- **мягкие** — разная страна, противоречащие организации, разные биографии.

Правила, которые важнее весов:

- совпадение имени и окружения без связующего признака — не выше
  `possible`;
- `confirmed` требует счёта не ниже 0.9 и двух независимых сильных
  признаков либо взаимных ссылок профилей;
- жёсткое «против» при сильном «за» — `conflicting`, без сильного «за» —
  `rejected`;
- сравнение фотографий как биометрия не является признаком ни с каким
  весом.

Пороги и веса меняются только вместе с тестами `test/osint-core.test.ts`.

## Противоречия

`src/osint/contradictions.ts` ищет разногласия в свойствах с единственным
значением: дата и место рождения, пол, ИНН, ОГРН, КПП, юрисдикция.
Разногласие не разрешается выбором «лучшего» источника: оно сохраняется
и показывается в отчёте. Даты разной точности согласуются: «1990» не
спорит с «1990-05-01». У свойств с многими значениями (почта, адрес,
работодатель) второе значение — дополнение, а не спор.

## Приватность журналов

OSINT почти целиком состоит из персональных данных третьих лиц.

- В журнал и метрики идёт маска (`i***@e***.com`, `+7***89`) или псевдоним:
  HMAC с секретом установки (`src/osint/masking.ts`).
- В маске всегда три звёздочки, чтобы по ней не угадывалась длина значения.
- Сами значения в телеметрию не отправляются.

## Выбор компонентов

| Компонент | Лицензия | Роль | Batch |
|---|---|---|---|
| libphonenumber-js 1.13.14 | MIT (проверено) | телефоны в E.164 | 1 |
| FollowTheMoney 4.11.0 | MIT (проверено) | модель сущностей | 2 |
| nomenklatura | проверяется в своём batch | кандидаты и сравнение для тождества | 2 |
| Maigret, WhatsMyName, Sherlock | проверяются в своём batch | username и цифровой след | 2 |
| SpiderFoot (только пассивные модули) | проверяется в своём batch | широкий пассивный сбор | 4 |
| theHarvester | проверяется в своём batch | организация → домены, почта, хосты | 4 |
| RDAP, RIPEstat, DNS, CT | открытые API | инфраструктура | 4 |
| yente | отложен | fuzzy matching | позже |

yente отложен по решению владельца: ему нужен Elasticsearch/OpenSearch
(+2–4 ГБ памяти), а данные OpenSanctions, с которыми его обычно используют,
для коммерческого продукта, по нашему пониманию, требуют отдельной
лицензии; это проверяется перед подключением. В первом релизе тождество
решают nomenklatura в `osint-worker` и `resolver.ts`.

Инструменты с лицензиями GPL и AGPL подключаются только отдельным
сервисом по HTTP, без копирования их кода в Evaself.

## Порядок ввода

| Batch | Что входит |
|---|---|
| OSINT-1 (этот) | доменный слой `src/osint/`, миграция 084, SQL-проверка границы арендатора, документ |
| OSINT-2 | `osint-worker` (Python, внутренняя сеть): FtM, nomenklatura, Maigret, WhatsMyName, Sherlock как проверка; типизированный клиент |
| OSINT-3 | репозиторий, оркестратор, итеративное расширение, сборщик SearXNG + Crawl4AI поверх `ResearchOrchestrator`, задания, отмена, идемпотентность, хранение и удаление, флаги |
| OSINT-4 | SpiderFoot (пассивный профиль), theHarvester, RDAP, RIPEstat, DNS, CT |
| OSINT-5 | инструменты Letta (`osint_investigate`, `osint_get_status`, `osint_get_report`, `osint_expand`, `osint_search_entity`, `osint_explain_relationship`, `osint_cancel`), отчёт, API Mini App, метрики, evals |
| OSINT-6 | реестры РФ (ЕГРЮЛ/ЕГРИП, Прозрачный бизнес, ЕФРСБ, арбитраж) через официальные API и выгрузки |
| далее | IntelOwl, Amass, GHunt (опционально), Aleph/OpenAleph, yente |

Флаги (`EVA_OSINT_ENABLED` и остальные) появятся в том batch, где контур
впервые что-то делает: флаг, который ничего не включает, только вводит в
заблуждение.
