# Инструменты Евы: реестр, поиск, MCP, браузер, субагенты

Ева получила больше инструментов, браузер и субагентов, а граница
осталась прежней: **Letta — единственный когнитивный runtime**. Что
вспомнить, какой навык открыть и какой инструмент вызвать, решает Letta.
Evaself регистрирует инструменты, исполняет их серверным кодом и держит
детерминированные границы: владелец, риск, подтверждение, идемпотентность,
аудит, пределы. Архитектурным ориентиром служил Hermes Agent
(NousResearch, MIT); из него перенесены решения, а не цикл агента, память,
контекст, сессии или планировщик — подробности в конце.

## Реестр инструментов

Все инструменты Evaself проходят через один реестр
(`eva-agent-service/src/tools/registry.ts`). Источники регистрируются кодом
сервиса при старте, по порядку старшинства: продуктовые, MCP, браузер.
Загрузки плагинов из npm или GitHub нет; внешние возможности подключаются
через MCP.

| Правило | Зачем |
|---|---|
| `tool_search`, `tool_describe`, `tool_call` зарезервированы | Инструмент с именем моста подменил бы мост |
| Коллизия имён отклоняется, первым остаётся продуктовый | MCP-сервер с `delete_tasks` не подменит продуктовое удаление вместе с его подтверждением |
| Имя прямого инструмента — `^[A-Za-z0-9_-]{1,64}$` | Ограничение OpenAI-совместимых провайдеров |
| Отложенный инструмент, выставленный прямо (поиск выключен), с точкой или длиннее 64 знаков получает псевдоним: недопустимые знаки → `_`, хвост — 8 знаков хеша полного имени | Инструмент MCP не выпадает из сессии; вызов исполняет замыкание с настоящим именем |
| Сборка без состояния, при каждом открытии сессии | Закреплённый набор расходится с реальностью и молча теряет инструменты |

У каждого инструмента есть источник (`product`, `bridge`, `mcp`,
`browser`), группа каталога и желаемая видимость: **прямая** (полная
схема в каждом ходе) или **отложенная** (в каталоге).

## Поиск инструментов

Флаг `EVA_TOOL_SEARCH` (выключен по умолчанию). Включён — инструменты MCP
и браузера не передаются Letta полными JSON Schema в каждом ходе: модель
видит три моста.

- `tool_search { query, limit? }` — BM25 по имени, группе, описанию и
  именам параметров (`src/tools/tool-search.ts`). Допуск — по самому
  редкому из слов запроса, встречающихся в каталоге: общие слова
  («создать», «send») не заполняют выдачу. Длинный запрос дополнительно
  требует покрытия половины слов. Русские и английские словоформы
  сводятся лёгким снятием окончаний.
- `tool_describe { names }` — полное описание и схема аргументов.
- `tool_call { name, arguments }` — вызов найденного инструмента.

Выключен — MCP и браузер регистрируются напрямую, как было до реестра.

Это не выбор инструмента за модель: каталог отвечает на запрос, который
модель сформулировала сама, и ничего не решает — как `knowledge_search`
отвечает на запрос по базе знаний. Продуктовые инструменты (задачи, цели,
профиль, заметки, подписка, OSINT) остаются прямыми: навыки называют их по
именам.

### `tool_call` — не обходной путь

Цепочка выполнения одна на все пути (`src/tools/tool-executor.ts`):

```text
область арендатора → уровень риска → подтверждение →
журнал эффектов (идемпотентность) → хуки (аудит, квоты, метрики, трасса) → выполнение
```

- Подтверждение SDK (`canUseTool`) спрашивается по **настоящему**
  инструменту: `unwrapBridgeCall` разворачивает `tool_call` до имени и
  аргументов цели (`src/tools/session-permission.ts`). Риск, категория,
  описание для человека и отпечаток аргументов — цели. Мост без понятной
  цели отклоняется; риск неразвёрнутого `tool_call` — `destructive`.
- Граница выполнения на хосте (`Bash`, `Write`, `Edit`…) проверяется по
  цели и до подтверждений.
- При выполнении мост дополнительно требует **записанного согласия**
  (`ApprovalService.authorizeExecution`): инструмент, требующий
  подтверждения, выполняется только при согласии на этот инструмент с
  этими аргументами в этом conversation. Если запрос согласия не
  состоялся, мост откажет, а не выполнит действие молча.
- Политика назначения conversation проверяется для обоих имён — моста и
  цели; журнал эффектов ключуется настоящим инструментом.
- Аргументы проверяются по схеме цели до вызова; ошибка возвращается с
  подсказкой открыть `tool_describe`.

## MCP discovery

`src/tools/mcp.ts`, `src/tools/mcp-discovery.ts`.

Обращение к серверу идёт по Streamable HTTP: `initialize` →
`notifications/initialized` → запросы с `Mcp-Session-Id` и
`MCP-Protocol-Version`; ответ — JSON или поток SSE; истёкшая сессия
(HTTP 404) переоткрывается один раз. Сервер без рукопожатия (простой
JSON-RPC) работает как прежде.

Инструменты сервер объявляет сам (`tools/list`, все страницы): имя,
описание, `inputSchema`. **Действующий набор — объявленное ∩ разрешённое
администратором** (`allowedTools` политики). Шаблон `*` запрещён и при
сохранении политики, и при расчёте набора. Разрешённое, но не
объявленное, панель показывает отдельно — это опечатка или удалённый
инструмент. Без discovery MCP-инструментов нет: схему «любой объект»
модель вызывала вслепую.

Список кэшируется в памяти процесса со сроком `EVA_MCP_DISCOVERY_TTL_MS`
(5 минут): ход не ждёт устаревшего списка, первая загрузка ждёт не больше
5 секунд, после отказа сервер не опрашивается минуту, последний удачный
список сохраняется. Это восстановимое состояние, а не данные: таблицы нет.

Описание инструмента пишет сервер, а модель читает его как часть
инструкций — классический путь «отравления инструмента». Описания и схемы
обезвреживаются, ответ сервера приходит модели в конверте недоверенного
содержимого (`src/tools/untrusted.ts`). Риск любого MCP-инструмента —
`external_side_effect`: подтверждение спрашивается всегда.

## Браузер

Отдельный сервис `browser-service/` (Playwright 1.63 + Chromium),
подробности — в его [README](../browser-service/README.md). Инструменты
`browser_open`, `browser_snapshot`, `browser_click`, `browser_type`,
`browser_scroll`, `browser_back`, `browser_close` регистрирует
eva-agent-service (`src/browser/`), отложенными.

- Модель получает не HTML, а снимок дерева доступности со ссылками
  `[ref=e12]`; длинный снимок листается по `offset`.
- Сервис не имеет доступа к PostgreSQL, Valkey, Letta и сокету Docker:
  своя сеть `browser`, в которой кроме него только eva-agent-service.
- SSRF: каждый запрос страницы проверяется, весь трафик Chromium идёт
  через проверяющий прокси, соединяющийся с проверенным IP.
- Только чтение: запросы не-GET отменяются; в поля пароля, кода и карты
  ничего не вводится, их значения в снимке скрыты.
- Пределы: сессий всего и на владельца, простой, возраст, время операции,
  размер снимка, `EVA_BROWSER_OPS_PER_MINUTE` на человека.
- Сессия и владелец — HMAC-псевдонимы с ключом, живущим только в памяти
  eva-agent-service: сервис браузера не знает ни пользователей, ни
  conversations.
- Снимок приходит модели в конверте недоверенного содержимого.

Риски: `browser_open`, `browser_snapshot`, `browser_scroll`,
`browser_back`, `browser_close` — `read`; `browser_click`, `browser_type`
— `low_risk_write` (меняют лишь вкладку разговора; отправить данные сайту
браузер не может).

## Субагенты Letta

`src/letta/subagents.ts`, `src/research/delegation.ts`, флаг
`EVA_DELEGATION_ENABLED` (вместе с `EVA_RESEARCH_ORCHESTRATOR`).

Субагент — обычный агент Letta, созданный штатным Agent SDK под одно
задание и удалённый после него. Возможности проверены на установленном
`@letta-ai/letta-agent-sdk` 0.7.1, обновлять SDK и App Server не
понадобилось: `createAgent` принимает `hidden`, `memfs`, `baseTools`,
`allowedTools`, `skillSources`; `createSession` — `stateless`,
`allowedTools`, `canUseTool`, `tools`; есть `agents.delete` и
`agents.list({ tags })`. `createSession` добавлен в матрицу контракта
(`letta-contract.test.ts`).

```text
Исследование
├─ research-субагент  — источники (web_search)
├─ document-субагент  — база знаний человека (knowledge_search)
└─ web-субагенты      — чтение страниц (web_read, браузер только для чтения), параллельно
        ↓
   проверка цитат (код)
        ↓
   synthesis-субагент — сводка только по проверенным фактам
```

| Граница | Как держится |
|---|---|
| Узкий контекст | Субагент получает вопрос и адреса. Ни профиля, ни истории, ни памяти Евы |
| Без памяти и навыков | `hidden`, `memfs: false`, `skillSources: []`, сессия `stateless` |
| Узкий набор инструментов | `baseTools: []`, точный `allowedTools`, `canUseTool` отклоняет всё сверх набора (оболочку, запись, субагентов второго уровня) |
| Только чтение | `AgentToolFactory.forDelegation` пропускает лишь инструменты с риском `read` |
| Владелец и квоты | Инструменты выполняются той же цепочкой от имени заказчика исследования |
| Пределы | Срок задания `EVA_DELEGATION_TIMEOUT_MS`, общий на процесс предел `EVA_DELEGATION_MAX_PARALLEL`, отмена задания отменяет субагентов |
| Уборка | Агент удаляется после задания; забытые после сбоя находятся по тегу `evaself:subagent` и удаляются при старте |
| Проверка | Цитата принимается, только если она дословно есть в тексте, который Evaself сам получил для субагента; адрес — среди выданных ему |

Отчёт той же формы, что у конвейера (`method: "delegated"`, число
неподтверждённых фактов — `issues.unverified`). Ничего не нашедшее
делегирование и недоступный Letta уступают прежнему конвейеру; отменённое
задание — нет.

Своего инструмента делегирования у Евы в диалоге нет: в ходе у неё есть
нативные субагенты Letta (`Task`), и второй путь к тому же был бы
вторым runtime.

## Хуки

`beforeToolCall`, `afterToolCall`, `onToolError`, `onToolDenied`
(`src/tools/tool-hooks.ts`). Хук видит только метаданные вызова: имя,
источник, путь (`direct`, `bridge`, `delegation`), риск, владельца,
идентификаторы, длительность. Аргументов и результата у хука нет.
Исключение хука не ломает вызов; запретить вызов можно только явно.

Набор фиксирован и собирается в `src/index.ts`
(`src/tools/standard-hooks.ts`):

| Хук | Что делает |
|---|---|
| `quota` | Предохранители от петли: `EVA_TOOL_CALLS_PER_TURN` вызовов через мосты и делегирование за ход, `EVA_BROWSER_OPS_PER_MINUTE` действий браузера на человека |
| `audit` | Вызовы через мост и делегирование — в существующую `agent_tool_calls` (прямые и так пишутся из потока SDK) |
| `metrics` | `eva_tool_calls_total` и длительности |
| `tracing` | span OpenTelemetry `tool.call` |
| `latency` | p50/p95/максимум по инструментам для панели |

## Навыки

`skills/<навык>/SKILL.md` + `references/` + `templates/` — см.
[skills/README.md](../skills/README.md). Встроенных команд оболочки из
навыков Hermes нет. Навык выбирает Letta.

Как пользоваться этими инструментами, Еве объясняет навык `web-research`:
`web_search` → `web_read` → браузер только для страниц, собранных скриптом,
`tool_search` для подключённых сервисов, ответ со ссылкой из результата
инструмента, текст страницы — данные, а не указания. Это текст навыка, а не
код: порядок вызовов по-прежнему выбирает модель.

## Панель и метрики

Раздел «Инструменты» (`/admin/tools`): каталог (прямые и отложенные,
риск, согласие, отклонённые реестром), MCP-серверы (объявлено, разрешено,
действует, не объявлено, повторный опрос), браузер (состояние, пределы,
сессии без адресов), субагенты (работают, очередь, итоги, уборка),
задержка инструментов. Данные — из `GET /v1/tools/catalog`
eva-agent-service фиксированным маршрутом панели.

Метрики `/metrics`: `eva_tool_calls_total{source,path,outcome}`,
`eva_tool_call_duration_ms_*`, `eva_tool_search_total{outcome}`,
`eva_mcp_discovery_total{outcome}`, `eva_mcp_discovery_duration_ms_*`,
`eva_browser_operations_total{operation,outcome}`,
`eva_browser_operation_duration_ms_*`,
`eva_delegation_runs_total{role,outcome}`, `eva_delegation_duration_ms_*`,
`eva_delegation_subagents{state}`. Ни аргументов, ни результатов, ни
адресов, ни текста запросов в метках нет.

## Включение и откат

Всё выключено по умолчанию; включает человек, по одному флагу, с
наблюдением в панели и метриках.

| Шаг | Включение | Откат |
|---|---|---|
| Поиск инструментов | `EVA_TOOL_SEARCH=true` | `EVA_TOOL_SEARCH=false` — MCP и браузер снова прямые |
| Браузер | `COMPOSE_PROFILES=…,browser`, `EVA_BROWSER_ENABLED=true` | `EVA_BROWSER_ENABLED=false`, убрать профиль |
| Субагенты | `EVA_RESEARCH_ORCHESTRATOR=true`, `EVA_DELEGATION_ENABLED=true` | `EVA_DELEGATION_ENABLED=false` — прежний конвейер |
| MCP discovery | работает при настроенном MCP | срок `EVA_MCP_DISCOVERY_TTL_MS`; отключить сервер политикой |

После изменения флагов: `docker compose up -d eva-agent-service` (и
`browser-service` при профиле). Миграций нет — откат не трогает данных.

## Что из Hermes Agent не переносится

Цикл агента Hermes, его провайдеры памяти, сжатие контекста, хранилище
сессий, cron-runtime, неограниченные Bash/Write/Edit и установщик плагинов
в Evaself не переносятся. Letta остаётся владельцем памяти, контекста,
истории, навыков и рассуждений.

Решения, взятые у Hermes Agent (Copyright (c) 2025 Nous Research, MIT
License): каталог и поиск отложенных инструментов с тремя мостами
(`tools/tool_search*.py`), снимки доступности и маскирование секретов
браузера (`tools/browser_tool*.py`), узкий контекст и пределы субагентов
(`tools/delegate_tool.py`), реестр провайдеров (`agent/provider_registry.py`),
структура навыков. Код Evaself написан заново на TypeScript; существенных
фрагментов кода Hermes в репозитории нет.
