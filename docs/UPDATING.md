# Обновление и rollback

```bash
make update-preview
make update
make rollback
```

Все версии зафиксированы в `versions.env`; плавающие `latest`/`stable` не
используются.

`make update`:

1. создаёт полный backup;
2. сохраняет текущий commit и `versions.env`;
3. получает новые версии и собирает образы;
4. применяет идемпотентные migrations;
5. запускает стек и `make doctor`;
6. автоматически выполняет rollback при неуспешной проверке.

Migration 004 добавляет реестр LLM и не удаляет старые данные. Для
существующей установки отдельный `LLM_CONFIG_ENCRYPTION_KEY` желательно
создать через `make configure`; до этого сервис безопасно использует
существующий `EVA_AGENT_API_KEY` как совместимый fallback.

Migrations `008`–`013` совместимо добавляют Telegram inbox/outbox, локаль,
профиль, цели, граф и purpose conversations. Не откатывайте их ручным
удалением таблиц: старый код игнорирует новые сущности, а `make rollback`
возвращает только код и версии образов.

После обновления:

```bash
make doctor
make test-llm
make shell-db
SELECT version FROM schema_migrations ORDER BY version;
```

Rollback возвращает код и версии образов, но не обращает назад уже
применённые совместимые migrations. Поэтому backup перед update обязателен.

## Что `make update` делает сам

Одна команда закрывает весь цикл — ручных шагов после неё нет:

1. зашифрованный backup и точка отката в `.rollback/`;
2. **локальные правки убираются в `git stash`**, если рабочее дерево грязное
   (раньше это молча отменяло обновление кода). Ничего не теряется:
   `git stash pop` возвращает всё обратно, команда печатает и список
   изменений, и способ их вернуть;
3. `git pull --ff-only` текущей ветки. Если ветка не совпадает с той, куда
   идут релизы, выводится предупреждение с командой переключения;
4. создание мастер-ключа Secret Store, если его ещё нет;
5. **`scripts/ensure-env-defaults.sh` добавляет в `.env` настройки, которые
   появились в `.env.example` с момента установки.** Существующие значения
   не трогаются никогда, новые секреты генерируются, пароли БД и админов —
   нет: их выдумывание отрезало бы стек от собственных данных, о таких
   случаях команда предупреждает отдельно;
6. сборка образов, миграции, пересоздание контейнеров, повторные миграции;
7. удаление устаревшей плоской сети `evaself-network`, если на ней уже
   никого не осталось;
8. финализация админ-панели, подключение таблиц к NocoDB;
9. `make doctor`, а при его провале — автоматический откат.

### Мастер-ключ

При первом создании ключа команда печатает предупреждение. Отнеситесь к нему
серьёзно: `secrets/eva-secrets-master-key` шифрует резервные копии и **в них
самих не содержится**. Потеря файла означает, что ни один архив не
восстановить. Скопируйте его за пределы сервера сразу.
