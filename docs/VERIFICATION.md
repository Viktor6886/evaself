# Проверка

GitHub Actions выполняет:

1. TypeScript typecheck и build;
2. unit-тесты `eva-agent-service`;
3. проверку, что Letta вызывается только через официальный Agent SDK;
4. три последовательных применения всех PostgreSQL migrations;
5. сборку всех локальных Docker-образов;
6. тесты Media Service с реальным ffmpeg;
7. запуск PostgreSQL, Valkey, App Server и `eva-agent-service`;
8. создание agent и conversation через Agent SDK;
9. сохранение связи в PostgreSQL;
10. изменение и сохранение настроек SDK без раскрытия capability token;
11. создание, изменение и удаление административного agent, а также
    создание и архивирование его conversation через официальный SDK;
12. создание двух LLM-конфигураций на изолированном mock endpoint;
13. проверку `/models`, последовательную активацию двух моделей и отсутствие
    API Key в ответах;
14. переключение модели у Telegram- и самостоятельного WebUI-agent;
15. реальный SDK-turn через WebUI chat API и потоковый mock LLM;
16. сравнение `agent_id`/`conversation_id` до и после переключения;
17. перезапуск App Server и `eva-agent-service`, затем повторную проверку
    LLM, SDK-настроек и идентификаторов.
18. HMAC, срок `auth_date` и запрет подмены Telegram ID во всех public
    WebApp-маршрутах;
19. профиль, IANA timezone/DST, цели, purpose conversations,
    четыре memory blocks и backend-подтверждение удаления;
20. durable inbox/outbox и разделение метрик PostgreSQL enqueue и Telegram
    delivery;
21. отсутствие зеркала переписки в PostgreSQL: история живёт в Letta;
22. согласованность версий Letta с lock-файлом: версия SDK у клиента и
    версия CLI, из которой собирается образ App Server, обязаны быть
    выведены из одного источника, иначе клиент и рантайм разъедутся;
23. контракты курсора длинных программ: запуск, продвижение, пауза и
    возобновление, терминальное состояние, граница арендатора, владение
    связанной целью и защита от устаревшей и повторной записи;
24. продуктовые факты хода: активная программа видна, приостановленная и
    завершённая не загрязняют обычный ход, а человек без программы
    получает прежний контекст;
25. маршрутизацию панели на живом Caddy: `/admin/letta`,
    `/admin/monitoring` и остальные разделы отдают страницу панели,
    `/admin` без слэша редиректит на `/admin/`, выведенные из эксплуатации
    имена только редиректят, а внутренний `/v1/*` наружу закрыт
    (`scripts/ci/test-admin-routing.sh`);
26. структуру административной поверхности: три публичных имени, ни одного
    отдельного `basic_auth`, никаких сервисов `letta-ui` и `uptime-kuma`
    (`scripts/ci/assert-single-admin-domain.py`);
27. виды операций, которые панель записывает: `start` и `stop` падали на
    CHECK, и кнопки «Запустить» и «Остановить» не работали ни разу
    (`scripts/ci/test-operation-kinds.sql` на живой базе плюс тест
    сервиса — по одному на каждую половину расхождения);
28. что каждому правилу в `admin-ui/public/ui.css` есть что оформлять
    (`scripts/ci/assert-live-css.py`): мёртвое правило ничего не ломает и
    потому копится незаметно.

## Локальные команды

```bash
cd eva-agent-service
npm ci
npm run typecheck
npm run build
npm test

cd ..
make validate
make test
```

## Проверка на VPS

```bash
sudo make install
make doctor
make test-llm
make list-models
```

Затем:

1. создайте agent и conversation в WebUI и выполните реальный ход в чате;
2. отправьте сообщение через прямой Telegram webhook;
3. запомните agent/conversation и добавьте в память проверочный факт;
4. добавьте второй реальный LLM и активируйте его;
5. убедитесь, что ответ использует новую модель, а факт из памяти доступен;
6. измените настройки SDK и перезапустите App Server и `eva-agent-service`;
7. убедитесь, что ID, память, SDK-настройки и активная LLM сохранились;
8. проверьте архивирование conversation и удаление отдельного test agent;
9. создайте заметку, запись бюджета и задачу через инструменты агента;
10. проверьте повтор задачи и heartbeat в часовом поясе пользователя;
11. выполните backup и restore на тестовом VPS;
12. проверьте, что панель нигде не показывает API Key или App Server token;
12а. откройте `/admin/agents`, создайте агента человеку и убедитесь, что
    `agent_links` и Letta показывают один и тот же `agent_id`;
12б. назначьте ручную подписку, снимите её и убедитесь, что оплаченный
    период вернулся, а решения видны в карточке доступа;
12в. отредактируйте персону в `/admin/persona`, сохраните и убедитесь, что
    счётчик применения назвал обновлённых агентов, а новый агент создался
    уже с новым текстом.
13. откройте Mini App из Telegram и проверьте «Сегодня», создание цели,
    «Начать»/«Готово», прогресс и автосохранение профиля;
14. перезапустите стек с queued inbox/outbox записью и убедитесь, что
    обработка продолжается без второго Letta turn;
15. проверьте структурированный лог `Telegram turn обработан` и измерьте
    служебную задержку до `letta_generation_ms` на тёплом cache;
16. отправьте боту сообщение, требующее длинного ответа, и убедитесь, что
    текст появляется в черновике по мере генерации, а не разом в конце:
    `time_to_first_delta_ms` в том же логе должен быть заметно меньше
    `letta_generation_ms`.

Docker, сетевые сертификаты, реальный LLM turn, Telegram и восстановление на
другом сервере зависят от VPS и не должны объявляться проверенными без
фактического выполнения.
