# Распознавание речи (STT)

Голосовые сообщения Telegram и WebApp распознаются через реестр
провайдеров: несколько конфигураций, основной и резервный провайдер на
каждый сценарий, переключение без перезапуска контейнеров.

## Кто что делает

```
Telegram voice / WebApp
      → eva-agent-service   (квоты, текст пользователю, разговор Евы)
      → media-service       (маршрут, провайдер, резерв, сам вызов STT)
      → провайдер
Распознанный текст
      → существующий conversation Евы → Letta Agent SDK → LLM
```

Разделение не случайное:

- **media-service (Python)** — адаптеры, матрица возможностей, схемы
  форм, валидация параметров, маршрутизация и резерв. Маршрутизация
  именно здесь, потому что только media-service видит сам файл: роутинг
  в TypeScript означал бы гонять аудио между контейнерами дважды.
- **admin-api (TypeScript)** — CRUD, RBAC, sudo, аудит, Secret Store,
  маршруты, телеметрия. Всё это уже есть в репозитории, второй такой
  механизм заводить нельзя.
- **eva-agent-service** — единственный, кто говорит с Letta App Server.
  Аудиофайлы в Letta, LLM и memory blocks не передаются никогда.

## Настройка

Панель → **Распознавание речи**.

1. **Добавить конфигурацию.** Провайдер, модель, ключ. Сохранение
   требует подтверждения паролем: оно записывает ключ.
2. **Проверить.** Настоящий запрос к провайдеру на коротком аудио.
   Показывает задержку, расшифровку и фактически отработавшую модель.
   Проверка ничего не активирует.
3. **Маршрутизация.** Назначить основной и резервный провайдер для
   сценария. Применяется немедленно.

Активация возможна только после успешной проверки: при провале маршрут
не меняется.

## Несколько ключей на провайдера

Кнопка **Ключи** на карточке открывает список. Ключей может быть до
двадцати; перебираются они сверху вниз.

Когда ключ перестаёт работать — исчерпан лимит, отозван, опечатка, —
media-service берёт следующий **внутри того же запроса**. Пользователь
ничего не замечает: та же модель, тот же провайдер, та же цена, разница
только в задержке на один неудачный вызов.

Это не то же самое, что резервный провайдер, и путать их нельзя:

| | смена ключа | резервный провайдер |
| --- | --- | --- |
| провайдер и модель | те же | другие |
| цена | та же | другая |
| сколько раз за аудио | пока не кончатся ключи | не более одного |
| считается fallback'ом | нет | да |

**Состояние ключа** панель показывает по итогам настоящих запросов:

| Состояние | Что значит | Когда вернётся |
| --- | --- | --- |
| работает | последний запрос прошёл | — |
| лимит исчерпан | провайдер ответил 429 | сам, через 15 минут |
| отвергнут провайдером | 401/403 | после вмешательства человека |

Выключенный вручную ключ остаётся в списке, но пропускается: временно
убрать ключ и удалить его насовсем — разные намерения. Включение обратно
снимает и автоматическую пометку — администратор мог заменить ключ на
стороне провайдера.

**Проверка прогоняет весь список**, а не только первый ключ, и
показывает результат по каждому. Иначе смысл списка теряется: «работает»
по первому ключу ничего не говорит про пятый, а узнать про опечатку в
нём хотелось бы не в тот день, когда первый упрётся в лимит.

Конфигурация считается неисправной, только когда отвергнуты **все**
ключи: один мёртвый ключ из пяти — не повод считать провайдера
сломанным.

Каждый ключ — отдельная запись в Secret Store. Списком в одной записи их
хранить нельзя: ротация одного перезаписывала бы остальные, а отозвать
один из пяти стало бы невозможно. Значения не возвращаются наружу ни в
одном ответе API — только подписи, порядок, состояние и счётчики.

## Провайдеры

Параметры сверены с официальной документацией **31 июля 2026 года**.
Список моделей не вечен — панель разрешает ручной ввод, и неизвестная
модель не требует правки кода. Дата сверки видна в редакторе.

### Deepgram

`https://api.deepgram.com/v1/listen` (batch), `wss://…` (streaming).
Единственный из четырёх с подтверждённым потоковым распознаванием.

Три вещи, которые легко сделать неправильно:

- Параметр называется **`keyterm`** в единственном числе и повторяется
  для каждого термина. Панель хранит массив, наружу уходит повторяющийся
  ключ.
- `keyterm` работает **только с nova-3** и возвращает 400 в паре с
  `language=multi`. Обе несовместимости отклоняются до отправки.
- `endpointing` осмыслен только в потоковом режиме. Умолчание Deepgram —
  10 мс; для русской речи с паузами это обрывает фразу на середине,
  поэтому универсальным значением оно не ставится.

### OpenAI

`https://api.openai.com/v1`. Модели `gpt-4o-transcribe`,
`gpt-4o-mini-transcribe`, `whisper-1`.

- **Только batch.** Потоковая расшифровка у OpenAI живёт в отдельном
  realtime-API с другим транспортом, поэтому `capabilities.streaming`
  здесь `false`.
- `timestamp_granularities` требует `response_format=verbose_json`,
  который поддерживает `whisper-1`. Модели `gpt-4o-transcribe` отвечают
  только `json`.
- **`confidence` не возвращается.** Поле в результате отсутствует, а не
  заполняется выдуманным числом.

### OpenRouter

`https://openrouter.ai/api/v1`. Тот же транспорт, что у OpenAI, но
отдельный провайдер в интерфейсе: свой каталог моделей и маршрутизация
по upstream-провайдерам.

- Полноценным realtime STT не является.
- `provider_options` проверяется как JSON-объект; неизвестные параметры
  автоматически не передаются.
- Фактически отработавший upstream и request ID показываются в
  результате проверки — счёт и качество зависят от них, а не от строки
  в поле «модель».
- Приватность: `data_collection: deny` и `zero_data_retention`
  ограничивают набор провайдеров, которым уйдёт аудио.

### Google Cloud Speech-to-Text

**v2**, а не v1: актуальный API адресует запрос через recognizer.

```
https://{location}-speech.googleapis.com/v2
  /projects/{project}/locations/{location}/recognizers/_:recognize
```

- Модели `chirp_2` недоступны в регионе `global` — нужен региональный
  endpoint.
- Учётные данные: администратор загружает service account JSON один
  раз. Backend проверяет MIME-тип, размер и обязательные поля, кладёт
  файл целиком в Secret Store, а в конфигурации остаются только
  `project_id`, маскированная почта и версия API. **Путь к файлу не
  хранится нигде, `private_key` не возвращается ни в браузер, ни в
  логи.**
- Синхронный `recognize` принимает до 10 МБ. Более длинные записи
  требуют `batchRecognize` и Cloud Storage — в этой версии не
  реализовано, вместо 400 от Google возвращается понятная ошибка.

## Маршрутизация и резерв

На каждый сценарий: основной, резервный, таймаут, предел длительности,
включённость.

| Сценарий | Что это |
| --- | --- |
| `telegram_voice` | Обычные голосовые Telegram |
| `webapp_voice_message` | Голосовая запись в WebApp |
| `webapp_live` | Потоковый режим живой Евы. Маршрут заведён, выключен |

`webapp_live` заведён заранее и выключен: сам режим ещё не написан, но
появление его не должно требовать новой миграции.

**Резерв запускается не более одного раза** и только на ошибках, которые
чинит смена провайдера: сеть, таймаут, 429, 5xx, недоступность. Битое
аудио, превышение лимита и провал валидации резерв отвергнет ровно так
же — платить за это второй раз незачем.

**Ошибка авторизации помечает конфигурацию неисправной.** Это не
временный сбой: пока администратор не заменит ключ, каждое следующее
сообщение упадёт так же. Помечается она, только когда отвергнуты все
ключи конфигурации, — см. «Несколько ключей на провайдера». Помеченная конфигурация пропускается как
резерв, пометка снимается при первом успехе или при обновлении снимка.

**Идемпотентность** — по `file_unique_id` Telegram: он не меняется при
повторной доставке апдейта, в отличие от `file_id`. Без этого ключа одно
голосовое оплачивалось бы дважды при таймауте вебхука.

## Горячее применение

Смена конфигурации или маршрута не требует перезапуска media-service,
eva-agent-service, агента Евы или всего Docker Compose.

admin-api собирает снимок — конфигурации с расшифрованными ключами плюс
маршруты — и отправляет его в media-service (`PUT /stt/runtime`), тем же
способом, каким уже отправляет настройки ASR/TTS. У media-service нет ни
доступа к PostgreSQL, ни мастер-ключа Secret Store: давать их сервису,
который принимает файлы извне, значит расширять поверхность атаки.

Снимок применяется целиком или не применяется вовсе и сохраняется на
диск с правами 0600 — media-service поднимается и работает, пока
admin-api ещё стартует. Уже выполняющийся запрос дорабатывает со старой
конфигурацией, новые идут по новой.

## Безопасность

- **Ключи только в Secret Store** (AES-256-GCM), под ссылками
  `sec_stt_<hex>`. В схеме конфигурации ключа нет даже в виде хеша: хеш
  необратим, провайдеру его не предъявишь, а ложное ощущение «секрет
  где-то тут» он создаёт.
- **API никогда не возвращает секрет** — только «настроен», дата и
  отпечаток. Отпечаток считается от ссылки, а не от значения.
- **SSRF.** Адрес проверяется дважды: до резолва (схема, порт, имена) и
  после резолва DNS и каждого редиректа — по фактическому IP. Только по
  имени защита не работает: `evil.example.com` может резолвиться в
  `127.0.0.1`. Запрещены `http://`, `file://`, loopback, link-local
  (включая `169.254.169.254`), приватные диапазоны, CGNAT и сети Docker.
  Приватный адрес разрешается отдельной настройкой под sudo — ради
  self-hosted STT; loopback не разрешается никогда.
- **Аудит.** Все операции пишутся в существующий `audit_log` с
  редактированием секретов. Аудио и полный текст личного разговора в
  журнал не попадают.
- **Пользователь не видит технических ошибок.** «Deepgram вернул HTTP
  429» ему нечего делать; приходит одна понятная фраза, причина
  остаётся в логе и в панели.

## Коды ошибок

| Код | Резерв | Что означает |
| --- | --- | --- |
| `stt_config_invalid` | нет | Параметры не приняты адаптером |
| `stt_secret_missing` | нет | Ключ не задан |
| `stt_auth_failed` | нет | Ключ отвергнут; конфигурация помечается |
| `stt_model_not_found` | нет | Модели нет у провайдера |
| `stt_audio_invalid` | нет | Файл не разбирается |
| `stt_audio_too_large` | нет | Больше лимита |
| `stt_audio_too_long` | нет | Длиннее лимита сценария |
| `stt_timeout` | **да** | Провайдер не ответил вовремя |
| `stt_rate_limited` | **да** | 429 |
| `stt_provider_unavailable` | **да** | Сеть или 5xx |
| `stt_transcription_failed` | **да** | Неразбираемый ответ |
| `stt_route_not_configured` | нет | Для сценария нет основного провайдера |
| `stt_all_providers_failed` | — | Отказали оба |

## Телеметрия

Три величины разведены и не смешиваются. Одно голосовое сообщение с
резервом — это:

- **1** распознавание для пользователя (`requests`);
- **2** обращения к провайдерам (`attempts`);
- **1** событие резерва (`fallbacks`);
- длительность аудио засчитывается **один раз**.

Квоты пользователей по-прежнему считает `usage_counters` (метрика
`voice_minutes`) — новая таблица его не заменяет и не дублирует.

Стоимость пишется только когда её можно посчитать достоверно по
опубликованному тарифу. Догадка хуже пустого поля: по ней оператор
примет решение, думая, что видит факт.

## Обновление работающей установки

`make update` не ломает голосовые сообщения.

При первом запуске после обновления admin-api переносит действующие
`MEDIA_ASR_*` в реестр: создаёт конфигурацию `migrated-default`,
переносит ключ в Secret Store и назначает её основной для
`telegram_voice`. Импорт **идемпотентен** — если конфигурации уже есть,
он не делает ничего, иначе перезапуск сервиса откатывал бы правки
администратора.

### Устаревшие переменные

`MEDIA_ASR_BASE_URL`, `MEDIA_ASR_API_KEY`, `MEDIA_ASR_MODEL`,
`MEDIA_ASR_LANGUAGE` объявлены **устаревшими**, но в этом релизе
продолжают работать: если маршрут не настроен, media-service распознаёт
по ним.

**Срок удаления: релиз 0.5.0.** К этому моменту распознавание должно
быть настроено через панель. Переменные `MEDIA_TTS_*` не затрагиваются —
синтез речи эта работа не меняет.

## Проверка на своих ключах

Ключей Deepgram, Google и OpenRouter у разработчика нет: адаптеры
покрыты тестами с локальным HTTP-моком, который отвечает по документации
провайдера (успех, 401, 429, 500, таймаут, битый JSON, отсутствие
`confidence`). Это проверяет сборку запроса и разбор ответа, но не
поведение живого API.

Расхождения с реальным API ловятся кнопкой **«Проверить»**: она делает
настоящий запрос вашим ключом и показывает и результат, и код ошибки.
После развёртывания стоит прогнать её по каждому заведённому провайдеру.

# Тесты админ-слоя требуют базы с применёнными миграциями:
