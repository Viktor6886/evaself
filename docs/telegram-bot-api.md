# Свой сервер Telegram Bot API: аудиофайлы до 350 МБ

Облачный Bot API (`api.telegram.org`) отдаёт ботам файлы **только до
20 МБ**. Запись встречи или лекции часто больше: час MP3 — 30–60 МБ. Файлы
любого размера бот получает только через свой сервер Bot API —
официальный `telegram-bot-api` в локальном режиме. В Evaself он
поставляется профилем compose `bot-api` и по умолчанию выключен.

## Как это работает

1. Человек присылает аудиофайл до 350 МБ (`EVA_AUDIO_FILE_MAX_MB`).
2. Свой сервер Bot API скачивает его из Telegram на свой диск — том
   `evaself_telegram_bot_api_data` — и отдаёт путь к файлу в `getFile`.
   По HTTP он файлы не раздаёт.
3. media-service забирает файл с этого тома и сразу удаляет оригинал.
   Том смонтирован только ему: агент читает изображения и документы
   через `POST /telegram/file` у media-service.
4. Запись режется на части не больше 20 МБ (WAV 16 кГц моно, до
   600 секунд) и распознаётся по порядку. С разделением говорящих в
   настройках провайдера части режутся с перекрытием, и в тексте голоса
   размечены через всю запись: «Голос 1», «Голос 2», …
   (`media-service/app/dialogue.py`).
5. Расшифровка приходит человеку файлом DOCX. Рабочая копия записи
   удаляется сразу после распознавания.
6. Полный текст хранится сутки (`work_documents`): по просьбе «сделай
   тезисами» Ева читает его (`document_read`) и присылает новый DOCX
   (`document_send`). Через сутки текст удаляется таймером агента; байты
   DOCX удаляются из очереди отправки сразу после доставки.

Длина записи ограничена отдельно: `MEDIA_MAX_AUDIO_SECONDS` (по умолчанию
два часа) и предел сценария `telegram_audio` в панели. Минуты
распознавания списываются по тарифу; запись длиннее остатка не
распознаётся.

## Включение

Нужно один раз — человеку, с доступом к аккаунту Telegram:

1. Войти на https://my.telegram.org, раздел **API development tools**,
   создать приложение и взять `api_id` и `api_hash`.
2. Вписать их в `.env`:

   ```
   TELEGRAM_API_ID=1234567
   TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
   ```

3. Включить флаг аудиофайлов, если он ещё выключен:
   `EVA_AUDIO_FILE_TRANSCRIPTS=true`.
4. Запустить:

   ```
   scripts/telegram-local-bot-api.sh enable
   ```

Скрипт выводит бота из облачного Bot API (`logOut`), включает профиль
`bot-api`, ставит `EVA_TELEGRAM_API_BASE_URL=http://telegram-bot-api:8081`
и перезапускает агент, панель и media-service. Агент при старте сам ставит
webhook уже через свой сервер.

Состояние — `scripts/telegram-local-bot-api.sh status`.

## Возврат в облако

```
scripts/telegram-local-bot-api.sh disable
```

Скрипт закрывает бота на своём сервере, останавливает его и возвращает
`EVA_TELEGRAM_API_BASE_URL=https://api.telegram.org`. После `logOut`
облако принимает бота обратно не раньше чем через 10 минут — так устроен
Telegram. Том `evaself_telegram_bot_api_data` остаётся; удалить его —
решение человека.

## Почему отдельный образ

`telegram-bot-api/Dockerfile` собирается поверх официального образа
`aiogram/telegram-bot-api` (версия — в `versions.env`) и меняет только uid
процесса на 10002. TDLib создаёт каталоги с правами 0700 и файлы с 0600:
прочитать и удалить скачанную запись может только тот же пользователь, а
media-service работает под uid 10002. CI проверяет, что uid совпадают.
