# osint-spiderfoot

[SpiderFoot](https://github.com/smicallef/spiderfoot) (MIT, master
`0f815a2`) за HTTP-обёрткой: только пассивные модули из закрытого списка,
только инфраструктурные события наружу.

## Почему не режим `passive`

В пассивный режим самого SpiderFoot входят модули утечек (psbdmp, scylla,
wikileaks), соцсетей, геолокации и разбора чужих страниц — контуру OSINT
всё это запрещено (`docs/OSINT.md`). Поэтому модули перечислены явно
(`ALLOWED_MODULES`): пассивный DNS, реестры ARIN/RIPE/GLEIF/BGPView, журналы
сертификатов и репутационные списки. `sfp_whois`, `sfp_pgp`, `sfp_keybase`
не включены: они приносят контакты людей.

## Что уходит наружу

Только события из `EVENT_KINDS`: хосты, домены, публичные IP, AS, сети,
названия компаний и LEI, записи DNS, репутационные отметки. Сайты на том
же сервере (`Co-Hosted Site`) идут отдельной группой `cohosts`: на общем
хостинге это чужие сайты, и к исследуемому домену они не привязываются. Имена людей,
физические адреса, геоданные, сырые ответы реестров и баннеры серверов
отбрасываются в контейнере.

Каждый скан идёт в своём временном каталоге, база SpiderFoot удаляется
после ответа; вывод процесса в журнал контейнера не пишется.

## Версия и зависимости

Релиз 4.0 распространяется под GPL-2.0 и тянет `cryptography<4`,
`pyOpenSSL<22`. Взята ветка master (MIT), закреплённая по коммиту;
зависимости подняты до версий без известных уязвимостей
(`requirements.lock`, pip-audit в CI).

## API

`POST /v1/scan` `{kind: domain|ip, target}` с заголовком `X-Osint-Key`.

```
docker build --target test osint-spiderfoot    # ruff + pytest + сверка списков
```
