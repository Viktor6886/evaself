# Шаги доработки Evaself

68 заданий: 00–33 — первый слой, 34–67 — второй. Каждый файл самодостаточен и
выполняется без чтения соседних шагов.

Шаги выполняются не по одному, а **batch**: одна ветка, один pull request, один
прогон CI, одно ревью. Границы batch и текущее состояние — в `PROGRESS.md`.
Протокол — в `CLAUDE.md`, раздел «Batch-протокол».

## Команда для запуска

Одна и та же на каждом batch, для любого агента:

```
Работай в репозитории Viktor6886/evaself.

Продолжи roadmap по протоколу репозитория: восстанови текущий batch
из PROGRESS.md или возьми следующий, выполни его полностью и остановись.
```

Инструкция для человека — `docs/HOW_TO_RUN.md`.

## Что читает агент

1. `PROGRESS.md` — где остановились, какой batch следующий.
2. Файлы шагов текущего batch.
3. `docs/IMPLEMENTATION_STATE.md` — что уже реализовано и что переиспользовать.
4. Модули, которые batch действительно меняет, — целиком, с их тестами.
5. Локальный `CLAUDE.md` подсистемы, если он есть.

Остальное — только когда конкретный вопрос потребовал.

## Шапка файла шага

- **Приоритет** — блок P0…P14.
- **Зависит от** — шаги, без которых этот не выполняется.
- **Feature flag** — под каким флагом приезжает изменение.
- **Размер** — оценка объёма: S, M, L. Не число pull request:
  pull request всегда один на batch.

Имени ветки в шапке нет намеренно: ветка одна на batch и называется
`batch/NN-<slug>`, где `NN` — номер batch, а `slug` — от первого шага в нём.

## Порядок

Шаги идут строго по возрастанию номера. Внутри batch порядок можно менять
только при отсутствии зависимости, указанной в шапке шага.

| Блок | Шаги | Смысл |
|---|---|---|
| P0 | 00–04 | Безопасность, изоляция арендаторов, жизненный цикл хода, параллелизм |
| P1 | 05–13 | Рабочая версия: восстановление, очереди, наблюдаемость, retention, обновление SDK, административный CRUD, версии |
| P2 | 14–22 | Качество ответа: инструменты, память, навыки, субагенты, evals |
| P3 | 23–30 | Продукт и масштаб: знания, исследования, интерфейсы, аналитика, backup, нагрузка, приёмка |
| P4 | 31–33 | Опционально: шардирование, расширения, dreaming — только по отдельной команде |
| P5 | 34–37 | Ledger потребления, квоты и гранты, платёжный слой, жизненный цикл подписки |
| P6 | 38–40 | Кнопки, опросы, контакты, файлы, персона и режимы тона |
| P7 | 41–44 | Речь, документы и изображения, генерация файлов, встречи |
| P8 | 45–48 | Лицензионный шлюз методик, PsychometricsEngine, импорт, экраны тестов |
| P9 | 49–54 | Интервью, формулировка 5P, «Моя жизнь», сигналы |
| P10 | 55–58 | Практики, антистресс, живой портрет, прозрачная память |
| P11 | 59–60 | Контакты, приглашения, совместимость, рефералы |
| P12 | 61–63 | Раздел «Пользователи», админка второго слоя, лендинг |
| P13 | 64–65 | Кризисный контур, итоговая интеграция второго слоя |
| P14 | 66–67 | Опционально: распорядок и питание, астрорефлексия |

Блоки P5–P13 начинаются после шага 30. Блок P4 не нужен для цели
«500 одновременно активных пользователей».

## Полные документы

- `docs/EVASELF_LAYER2_PLAN.md` — план второго слоя: что исключено как
  дубликат, снятые противоречия, модель данных, критерии приёмки.
- `docs/evaself-consolidated-ts-v1.0.docx` — консолидированное техническое
  задание.
- `docs/evaself-claude-code-prompt-v2.0.docx` — те же шаги как документ с
  анализом исходного промпта.
