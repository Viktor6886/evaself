# Шаги доработки Evaself

Задания, по которым Evaself строилась. Каждый файл самодостаточен и
выполняется без чтения соседних шагов.

> **Автоматически продолжать этот roadmap нельзя.**
>
> Часть заданий написана до перехода на Letta-native архитектуру и строит
> подсистемы, которых в репозитории больше нет. Такие файлы лежат в
> `prompts/archive/` и заданием не являются: ToolGateway, temporal-память,
> Memory Curator, Memory Doctor, Hybrid Retrieval, свои навыки и SkillRouter,
> субагенты Evaself, обновление SDK до 0.6.0, эксперимент с dreaming. Всё это
> удалено в PR #188 и заменено штатными возможностями Letta.
>
> Прежде чем брать любой шаг, сверь его с разделом «Главная граница» в
> `CLAUDE.md`. Шаг, который строит собственную память, собственное
> извлечение, свой роутер навыков или подходов, свой compaction или свою
> ротацию conversation, выполнять нельзя.

Работу задаёт человек. Порция работы — **batch**: одна ветка, один pull
request, один прогон CI, одно ревью. Текущее состояние — в `PROGRESS.md`,
протокол — в `CLAUDE.md`, раздел «Batch-протокол».

Инструкция для человека — `docs/HOW_TO_RUN.md`.

## Что читает агент

1. `PROGRESS.md` — где остановились и что считается точкой отсчёта.
2. Файлы шагов текущего batch.
3. `docs/IMPLEMENTATION_STATE.md` — что уже реализовано и что переиспользовать.
4. Модули, которые batch действительно меняет, — целиком, с их тестами.
5. Локальный `CLAUDE.md` подсистемы, если он есть.

Остальное — только когда конкретный вопрос потребовал.

## Шапка файла шага

- **Приоритет** — блок P0…P14.
- **Зависит от** — шаги, без которых этот не выполняется.
- **Feature flag** — под каким флагом приезжает изменение.
- **Размер** — оценка объёма: S, M, L. Не число pull request:
  pull request всегда один на batch.

Имени ветки в шапке нет намеренно: ветка одна на batch и называется
`batch/NN-<slug>`, где `NN` — номер batch, а `slug` — от первого шага в нём.

## Порядок

Внутри порции шаги идут по возрастанию номера; менять порядок можно только
при отсутствии зависимости, указанной в шапке шага. Между порциями порядок
задаёт человек: сквозной очереди шагов больше нет.

Блоки ниже — историческая карта заданий. Архив прежнего roadmap и причина
архивации — `docs/ROADMAP_ARCHIVE.md`.

| Блок | Шаги | Смысл |
|---|---|---|
| P0 | 00–04 | Безопасность, изоляция арендаторов, жизненный цикл хода, параллелизм |
| P1 | 05–13 | Рабочая версия: восстановление, очереди, наблюдаемость, retention, административный CRUD, версии (11 в архиве) |
| P2 | 14–22 | Качество ответа: 14–21 в архиве, актуальны только evals (22) |
| P3 | 23–30 | Продукт и масштаб: знания, исследования, интерфейсы, аналитика, backup, нагрузка, приёмка |
| P4 | 31–33 | Опционально: шардирование и расширения — только по отдельной команде; dreaming в архиве, он штатный |
| P5 | 34–37 | Ledger потребления, квоты и гранты, платёжный слой, жизненный цикл подписки |
| P6 | 38–40 | Кнопки, опросы, контакты, файлы, персона и режимы тона |
| P7 | 41–44 | Речь, документы и изображения, генерация файлов, встречи |
| P8 | 45–48 | Лицензионный шлюз методик, PsychometricsEngine, импорт, экраны тестов |
| P9 | 49–54 | Интервью, формулировка 5P, «Моя жизнь», сигналы |
| P10 | 55–58 | Практики, антистресс, живой портрет, прозрачная память |
| P11 | 59–60 | Контакты, приглашения, совместимость, рефералы |
| P12 | 61–63 | Раздел «Пользователи», админка второго слоя, лендинг |
| P13 | 64–65 | Кризисный контур, итоговая интеграция второго слоя |
| P14 | 66–67 | Опционально: распорядок и питание, астрорефлексия |

Блоки P5–P13 начинаются после шага 30. Блок P4 не нужен для цели
«500 одновременно активных пользователей».

## Полные документы

- `docs/ROADMAP_ARCHIVE.md` — объяснение, почему прежний roadmap отменён.

Архивные prompts не являются очередью работ. Новая работа начинается только
с явно поставленной человеком задачи.
