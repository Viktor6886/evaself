# Шаг 1. Срочные исправления безопасности и Security Audit

- **Приоритет:** P0
- **Зависит от:** шаг 0
- **Feature flag:** EVA_SECURITY_AUDIT (только для отчёта)
- **Объём:** 1 PR, архитектура не меняется
- **Ветка:** `claude/step-01-security-fixes`

> Перед началом прочитай `CLAUDE.md` и `PROGRESS.md` в корне репозитория.
> Выполни только этот шаг, обнови `PROGRESS.md`, открой pull request и остановись.

---

Прочитай CLAUDE.md и следуй его инвариантам.

ЦЕЛЬ:
Устранить подтверждённые конфигурационные риски до повышения параллелизма и добавить диагностику критических ошибок конфигурации.

СНАЧАЛА ПРОВЕРЬ:
Фактическое поведение проверки MEDIA_SERVICE_TOKEN, права Unix-сокета updater, окно приёма Telegram initData, наличие rate limit на публичных маршрутах, маршруты Caddy и защиту NocoDB и Letta UI, наличие Dependabot или Renovate, реализацию Secret Store и редактирование trace.

СДЕЛАЙ:
1. В production включи fail-fast, если MEDIA_SERVICE_TOKEN пуст. В режиме разработки поведение сохрани.
2. Если права сокета updater действительно 0666, измени на 0660 с выделенной группой и проверь список контейнеров, имеющих доступ к этому volume и к Docker socket.
3. Сократи окно приёма initData Telegram Mini App до 300–600 секунд, введи короткоживущую серверную сессию после первой проверки и защиту от повтора.
4. Добавь rate limit для /public/*, Telegram webhook и других публичных маршрутов: раздельные лимиты по IP и по проверенной Telegram-идентичности. Идентификатор пользователя из браузера не является ключом авторизации.
5. Включи мониторинг зависимостей: Dependabot или Renovate, npm audit, pip audit, secret scanning, закреплённые версии GitHub Actions.
6. Проверь Secret Store: AES-256-GCM, мастер-ключ вне backup, процедура ротации, редактирование trace.
7. Реализуй Security Audit как раздел Admin UI или диагностический endpoint. Он должен выявлять: открытые порты, пустые и дефолтные учётные данные, отсутствующие ключи шифрования, небезопасные настройки провайдеров, агентов без ограничений, отключённый аудит, дрейф политик хранения, устаревшие зависимости. Каждая находка имеет уровень критичности и ссылку на конкретный параметр.

НЕ ДЕЛАЙ В ЭТОМ ШАГЕ:
Не меняй схему БД. Не трогай Telegram inbox/outbox, session pool, LLM Router и очереди. Не вводи параллелизм.

ТЕСТЫ:
Отклонение недействительного, просроченного и повторно предъявленного initData; работоспособность действительной сессии Mini App; остановка production при пустом media-токене; недоступность updater неавторизованному контейнеру; отсутствие секретов, PII и reasoning в логах и ошибках; регрессия существующих сценариев Telegram, Mini App, админки и backup.

ГОТОВО, КОГДА:
Production не стартует с критически небезопасными значениями, публичные поверхности имеют rate limit и проверенную идентичность, Security Audit возвращает список находок с уровнями критичности, существующие сценарии не сломаны.

ОТЧЁТ:
По формату из CLAUDE.md. Приложи вывод Security Audit на текущей конфигурации.
