- **Зависит от:** шаги 0–2

- **Объём:** 1 PR
- **Ветка:** `step/03-turn-lifecycle`

> Выполни только этот шаг: проверки, `PROGRESS.md`, pull request, мерж по условиям

---

Прочитай CLAUDE.md и следуй его инвариантам. Канонический список состояний хода находится там же.

ЦЕЛЬ:
Фиксировать каждый ход и его контрольные точки, не меняя текущий путь обработки сообщения.

СНАЧАЛА ПРОВЕРЬ:
Есть ли уже в схеме и коде совместимая машина состояний или таблица исполнения хода. Если есть — расширяй её, второй не создавай.

СДЕЛАЙ:
1. Генерируй стабильный run_id до начала выполнения.
2. Формируй ключ идемпотентности из канала, идентификаторов update и conversation. При повторах он не меняется.
3. Связывай ход с записями inbox, пользователем, агентом, conversation, списанием квоты, версиями prompt и flow, run и сессией Letta, записью outbox и трассой.
4. Фиксируй переходы состояний, lease, номер попытки, безопасный код ошибки и барьер отмены.
5. Валидируй переходы кодом: недопустимый переход отклоняется и логируется.
6. Включай запись жизненного цикла флагом EVA_TURN_LIFECYCLE, не изменяя текущий worker.
7. Добавь Prometheus-совместимый endpoint /metrics с метриками: глубина и возраст inbox и outbox, активные ходы, время ожидания и длительность хода, блокировки пользователей, активные и простаивающие сессии Letta, пул PostgreSQL, лаг event loop.
8. В таблице жизненного цикла не сохраняй сырые промпты, ответы, аргументы инструментов и reasoning.

НЕ ДЕЛАЙ В ЭТОМ ШАГЕ:
Не вводи параллельную обработку. Не меняй session pool. Не переноси ничего в очереди. Не меняй ответы пользователю.

МИГРАЦИИ:
Только добавление. Forward-миграция работает со старым кодом, down-миграция не уничтожает строки. Индексы — CONCURRENTLY.

ТЕСТЫ:
Один update создаёт один логический ход; повторный update не создаёт вторую успешную запись и второе списание квоты; жизненный цикл восстанавливается после перезапуска; запись в shadow не меняет ответ и не увеличивает задержку сверх согласованного бюджета; недопустимый переход отклоняется.

ГОТОВО, КОГДА:
При включённом флаге каждый ход имеет run_id и полную последовательность состояний, /metrics отдаёт перечисленные метрики, поведение пользователя не изменилось.

ОТЧЁТ:
По формату из CLAUDE.md. Приложи пример записи жизненного цикла одного хода без пользовательского текста.
