Прочитай CLAUDE.md и следуй его инвариантам.

ЦЕЛЬ:
Исключить закрытие активной сессии Letta, обеспечить безопасную отмену хода и восстановление после сбоя без повторной генерации и повторных побочных эффектов.

СНАЧАЛА ПРОВЕРЬ:
Текущий session pool, его политику вытеснения, обработку ошибок хода и поведение при смене настроек SDK.

СДЕЛАЙ:
1. Введи в структуру сессии счётчик активных ходов, признак закрытия и идентификатор shard. Увеличивай счётчик перед ходом, уменьшай в блоке finally.
2. Запрети закрытие и вытеснение сессии при ненулевом счётчике активных ходов. Закрывай только простаивающие сессии по LRU.
3. При сбое хода удаляй только повреждённую сессию.
4. Смена настроек SDK выполняет graceful drain с таймаутом, а не немедленное закрытие.
5. Реализуй барьер отмены: отменённый ход останавливает генерацию и стриминг, помечается отменённым и никогда не доставляет поздний ответ. Отмена не откатывает уже выполненные внешние действия и не удаляет сохранённую память.
6. Реализуй журнал побочных эффектов инструментов. Ключ исполнения детерминирован и выводится из run_id, идентификатора вызова инструмента и его имени. Перед выполнением создаётся запись: при существующей успешной записи возвращается прежний результат, при выполняющейся — повтор не выполняется, при повторяемой ошибке применяется индивидуальная политика. Хранится только безопасный результат или его хэш.
7. Реализуй восстановление незавершённого хода: найти запись по истёкшему lease, проверить outbox, проверить факт отправки сообщения, сверить состояние через Letta по идентификатору run, при активном ходе продлить ожидание, при готовом результате создать только запись outbox без обращения к модели, проверить журнал побочных эффектов и повторить ход только при доказанном отсутствии завершённого.
8. Каждую попытку восстановления фиксируй отдельной записью с причиной, найденным состоянием, решением и результатом.

НЕ ДЕЛАЙ В ЭТОМ ШАГЕ:
Не вводи шардирование. Не переноси восстановление в BullMQ — это будет отдельным шагом. Не меняй dispatcher.

ТЕСТЫ:
Инъекция сбоя в шести точках: до отправки в Letta, после отправки, во время стриминга, после получения результата, до фиксации outbox, после фиксации и во время доставки. Плюс: отмена во время генерации, отмена во время выполнения инструмента, потеря блокировки, перезапуск сервиса при активных ходах, повторный вызов инструмента с тем же ключом.

ГОТОВО, КОГДА:
Активная сессия не вытесняется ни при каких условиях, один update даёт не более одного логического хода при любом из шести сбоев, один вызов инструмента даёт не более одного побочного эффекта, отменённый ход не доставляет поздний ответ.

ОТЧЁТ:
По формату из CLAUDE.md. Приложи таблицу результатов инъекции сбоев.
