Прочитай CLAUDE.md и следуй его инвариантам.

ЦЕЛЬ:
Перевести runtime на @letta-ai/letta-agent-sdk 0.6.0 и подключить @letta-ai/letta-client 1.12.1 как административный control plane. Это шаг с явной точкой решения.

СНАЧАЛА ПРОВЕРЬ:
Текущие версии Agent SDK, Letta Code, App Server и Node.js. Официальные требования совместимости версий 0.6.0 и 1.12.1. Совместим ли развёрнутый App Server с требуемым контрактом.

СДЕЛАЙ:
1. Напиши contract-тесты на текущей версии до обновления: создание, изменение и удаление агента; создание, список и архивирование conversation; стриминг; отмена хода; memory blocks; инструменты; approvals; skills; research-conversation; экспорт и импорт; восстановление сессии.
2. Выполни обновление в отдельной ветке. Использование @latest для SDK, CLI и GitHub Actions запрещено — только точные версии в lock-файле.
3. Прогони contract-тесты, интеграционные тесты, evals при их наличии и полный smoke стека на обновлённой версии.
4. ТОЧКА РЕШЕНИЯ. Если все проверки зелёные — включай EVA_LETTA_SDK_060 в режиме canary и сохрани предыдущий артефакт развёртывания для отката. Если хотя бы одна проверка красная или App Server не поддерживает контракт — ОСТАНОВИСЬ, не обновляй runtime и доложи: какая именно операция не поддержана, какая версия App Server требуется и что блокирует. Не эмулируй отсутствующие операции скрытыми REST-запросами.
5. Подключи LettaAdminClient за интерфейсом и используй официальный клиент только для подтверждённых операций. Runtime-ходы продолжают идти через Agent SDK. Второй путь выполнения диалога не создаётся.
6. Если точечное изменение memory block официально не поддержано, используй честно обозначенный runtime override: предпросмотр и diff, статус synced, pending, runtime_override или failed, повтор синхронизации при появлении официальной возможности. Скрытых мутаций быть не должно.
7. Заблокируй удаление агента и conversation при активном ходе или ожидающем approval.

НЕ ДЕЛАЙ В ЭТОМ ШАГЕ:
Не расширяй функциональность админки — это следующий шаг. Не меняй memory blocks и их набор. Не пересоздавай существующих агентов.

ТЕСТЫ:
Contract-набор воспроизводим и проходит на обеих версиях; откат возвращает прежний lock-файл и артефакт; неподдерживаемая операция отображается как неподдерживаемая, а не как молчаливый успех; существующие агенты не пересозданы; backup и restore сохраняют mapping и статус override.

ГОТОВО, КОГДА:
Либо runtime работает на 0.6.0 с зелёными contract-тестами и проверенным откатом, либо есть отчёт с точной причиной блокировки и системой, оставшейся на прежней версии без деградации.

ОТЧЁТ:
По формату из CLAUDE.md. Обязательно приложи матрицу совместимости: операция, поддержана, версия.
