# Шаг 12. Полный административный CRUD

- **Приоритет:** P1
- **Зависит от:** шаг 11
- **Feature flag:** EVA_ADMIN_CRUD
- **Объём:** 2–3 PR
- **Ветка:** `claude/step-12-admin-crud`

> Перед началом прочитай `CLAUDE.md` и `PROGRESS.md` в корне репозитория.
> Выполни только этот шаг, обнови `PROGRESS.md`, открой pull request и остановись.

---

Прочитай CLAUDE.md и следуй его инвариантам.

ЦЕЛЬ:
Дать администратору полное управление сущностями Евы через официальные интерфейсы, с предпросмотром, аудитом и откатом.

СНАЧАЛА ПРОВЕРЬ:
Что уже реализовано в Admin UI и Letta UI. Какие операции подтверждены contract-тестами предыдущего шага. Существующие RBAC, sudo и журнал аудита.

СДЕЛАЙ:
Реализуй CRUD и диагностику для следующих областей, переиспользуя существующие механизмы авторизации и аудита:
1. Агенты и conversations: список, поиск, фильтры, создание, изменение, архивирование, безопасное удаление, mapping, назначение, версии, сессии, активные ходы, экспорт и импорт.
2. Memory blocks: просмотр и редактирование блока одного агента, группы агентов, всех агентов и шаблона новых агентов. Шаблоны с версиями, предпросмотр и diff, dry-run, массовое применение с исключениями, история и откат. Изменение шаблона новых агентов не изменяет существующих без отдельной команды.
3. Инструменты: реестр, политики по назначению conversation, уровни риска, включение и отключение, версии.
4. Approvals: ожидающие и решённые запросы, риск, инициатор, срок действия, отзыв постоянного правила.
5. Навыки: каталог, версия, статус, хэш, ошибки индексации, статистика выбора, включение, отключение, переиндексация, тестовый прогон маршрутизации.
6. Исследования: планы, источники, утверждения, бюджеты, запуски, отмена.
7. Evals: наборы, датасеты, прогоны, оценки, состояние release gate.
8. Восстановление: жизненный цикл ходов, попытки, отмена, журнал побочных эффектов, ручная сверка, безопасный повтор доставки.
9. Расширения: реестр, версии, права, kill switch — как read-only заглушка, если сам механизм ещё не реализован.
10. Правила: любое управляющее действие валидируется, опасное требует подтверждения, ограничено ролью и попадает в аудит. Изменения конфигурации применяются без пересборки только через версионируемый Config Service. Администратор по умолчанию не видит сырой чувствительный payload.

НЕ ДЕЛАЙ В ЭТОМ ШАГЕ:
Не удаляй Letta UI и NocoDB — только после доказанного паритета в отдельном шаге. Не реализуй функциональность подсистем, которых ещё нет; для них делай честные read-only разделы с пометкой о статусе.

ТЕСТЫ:
Матрица ролей; CSRF, сессии и sudo; отсутствие сырых секретов и внутренних ошибок в ответах; подтверждение опасных действий; полнота аудита; неподдерживаемая SDK-операция отображается честно.

ГОТОВО, КОГДА:
Все десять областей доступны, каждое действие имеет предпросмотр либо подтверждение, аудит и откат.

ОТЧЁТ:
По формату из CLAUDE.md.
