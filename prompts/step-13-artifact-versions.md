# Шаг 13. Единый реестр версий: prompts, flows, skills и policies

- **Приоритет:** P1
- **Зависит от:** шаг 12
- **Feature flag:** EVA_ARTIFACT_VERSIONS
- **Размер:** M

> Протокол — `CLAUDE.md`. Шаг выполняется внутри batch: pull request, CI и ревью — на batch, не на шаг.

---

ЦЕЛЬ:
Не создавать четыре почти одинаковые системы версий. Один реестр артефактов с неизменяемыми публикациями.

СНАЧАЛА ПРОВЕРЬ:
Существующие таблицы версий конфигурации и любые зачатки версионирования промптов или сценариев.

СДЕЛАЙ:
1. Если существующего механизма недостаточно, введи общую модель: стабильное определение артефакта, неизменяемая версия артефакта, публикация по окружению или метке с указателем раскатки и отката.
2. Типы артефактов включают минимум prompt, flow, skill, policy и шаблон memory block. Prompt и flow остаются независимыми типами и версионируются отдельно.
3. Опубликованную версию нельзя изменить: запрет реализуется на уровне схемы, а не соглашением. Изменение создаёт новую версию.
4. Поддержи валидацию, контрольную сумму, родительскую версию, семантический diff, предпросмотр, результат тестов, утверждение, публикацию кандидата, процентную раскатку и откат одним действием.
5. Каждый ход, задание, вызов инструмента, инсайт, исследование и прогон evals фиксирует точные версии использованных артефактов.
6. Git остаётся средой разработки проверяемых системных артефактов, публикация в PostgreSQL — источником истины во время выполнения. Langfuse хранит только идентификатор версии.

НЕ ДЕЛАЙ В ЭТОМ ШАГЕ:
Не создавай отдельные реестры для промптов и сценариев. Не переноси пока навыки — это шаги 19 и 20.

ТЕСТЫ:
Опубликованная строка неизменяема на уровне схемы; откат меняет указатель публикации и не переписывает историю; прогон воспроизводимо указывает версии; параллельные реестры отсутствуют.

ГОТОВО, КОГДА:
Любой ход можно воспроизвести, зная версии артефактов, а откат выполняется одним действием без потери истории.

ОТЧЁТ:
По формату из CLAUDE.md.
