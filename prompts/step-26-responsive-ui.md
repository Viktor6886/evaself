# Шаг 26. Адаптация Web UI и Admin UI под смартфоны

- **Приоритет:** P3
- **Зависит от:** шаги 12, 25
- **Feature flag:** нет (изменение вёрстки)
- **Объём:** 1–2 PR
- **Ветка:** `step/26-responsive-ui`

> Перед началом прочитай `CLAUDE.md` — там протокол автономной работы.
> Выполни только этот шаг: проверки, `PROGRESS.md`, pull request, мерж по условиям
> из протокола. Затем возьми следующий шаг порции. На отметке ⏸ остановись.

---

Прочитай CLAUDE.md и следуй его инвариантам.

ЦЕЛЬ:
Сделать пользовательский и административный интерфейс полноценно пригодными для работы со смартфона при разных разрешениях.

СНАЧАЛА ПРОВЕРЬ:
Текущую вёрстку Mini App и Admin UI, наличие фиксированных ширин, горизонтальной прокрутки, таблиц без адаптации и элементов, недоступных на узком экране.

МАТРИЦА РАЗРЕШЕНИЙ:
320×568, 360×640, 375×667, 390×844, 412×915, 430×932, 768×1024 и десктоп. Проверка выполняется на каждом из них.

СДЕЛАЙ:
1. Убери горизонтальную прокрутку страницы. Широкие таблицы, диаграммы и блоки кода прокручиваются внутри собственного контейнера.
2. Минимальная область нажатия — 44×44 логических пикселя, между интерактивными элементами есть отступ.
3. Учитывай безопасные зоны и вырезы экрана, поведение экранной клавиатуры и аппаратную кнопку «Назад» в Android.
4. Для каждого экрана определи состояния загрузки, пустоты и ошибки. Мёртвых элементов, не выполняющих действие, быть не должно.
5. Таблицы Admin UI на узком экране превращаются в карточки с ключевыми полями и раскрытием подробностей.
6. Опасные действия на мобильном требуют явного подтверждения и не срабатывают по случайному касанию.
7. Шрифты и контраст соответствуют требованиям читаемости; интерфейс работает в светлой и тёмной теме, если она поддерживается.
8. Проверь производительность на мобильном: объём начальной загрузки, отсутствие блокирующих запросов, отзывчивость списков.

НЕ ДЕЛАЙ В ЭТОМ ШАГЕ:
Не меняй API и бизнес-логику. Не переписывай интерфейс на другой фреймворк. Только вёрстка, состояния и тесты.

ТЕСТЫ:
Playwright с device-матрицей по всем перечисленным разрешениям для основных экранов Mini App и Admin UI; проверка отсутствия горизонтальной прокрутки; проверка размеров областей нажатия; проверка поведения при открытой клавиатуре; проверка кнопки «Назад».

ГОТОВО, КОГДА:
Все основные экраны проходят device-матрицу, горизонтальная прокрутка отсутствует, опасные действия защищены от случайного касания.

ОТЧЁТ:
По формату из CLAUDE.md. Приложи результаты прогонов по каждому разрешению.
