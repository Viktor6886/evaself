# Шаг 61. Раздел «Пользователи» в административной панели

- **Приоритет:** P12
- **Зависит от:** шаги 12, 34–37
- **Feature flag:** EVA_ADMIN_USERS
- **Размер:** L

> Протокол — `CLAUDE.md`. Шаг выполняется внутри batch: pull request, CI и ревью — на batch, не на шаг.

---

**ЦЕЛЬ.** Дать оператору работу с конкретным пользователем без прямых запросов к базе.

**СНАЧАЛА ПРОВЕРЬ.** Что уже сделал шаг 12: RBAC, sudo, аудит, разделы агентов и conversations. Здесь добавляется раздел пользователей поверх существующего Admin API.

**СДЕЛАЙ.**
1. Навигация: обзор, пользователи, интеграции, тарифы, платежи, агенты, рассылки, мониторинг, backup, настройки, аудит.
2. На обзоре — кликабельные агрегаты: всего, новые и активные, платные и пробные, истекающие, заблокированные, агенты с ошибками, неполные профили.
3. Список пользователей: пользователь, Telegram, статус, тариф, дата подписки, гранты, использование, агент, последняя активность, регистрация, ошибки, действия.
4. Поиск: имя, фамилия, отображаемое имя, username без учёта символа и регистра, Telegram user ID, chat ID, внутренний идентификатор, идентификатор и имя агента, реферальный код, идентификатор платежа, разрешённый email плательщика, административные заметки. Числовые идентификаторы искать сначала точным совпадением, текст — через триграммы и полнотекстовый поиск, задержка ввода 250–400 мс.
5. Фильтры сохраняются в адресе страницы. Поддержать фильтры по подписке, статусу, агенту, активности, заполненности профиля, использованию модулей и источнику регистрации. Сортировки по имени, датам, тарифу, оплатам, сообщениям, токенам, ошибкам, агенту и квоте.
6. Карточка пользователя с вкладками: обзор, подписка, гранты и лимиты, агент, переписка, память и профиль, модули, платежи, технические данные, аудит.
7. Подписка: текущий тариф, источник, период, статус, автопродление, внешние идентификаторы, время синхронизации, ручной override; смена немедленно или после периода; продление днями или новой датой; предпросмотр «было и станет»; обязательная причина; отдельное событие подписки вместо прямого редактирования остатка; история событий с ключом идемпотентности; вебхук не затирает ручной override.
8. Переписка: только метаданные по умолчанию. Просмотр содержимого требует отдельного права, указания причины и записи в аудит. Вложения — по временным подписанным ссылкам. Переписка не используется для обучения без согласия.
9. Память и профиль: администратор исправляет только технические ошибки, помечает устаревшее, запрещает использование и запускает синхронизацию. Произвольное добавление психологических характеристик запрещено.
10. Служебное сообщение пользователю: текст или шаблон, кнопка, тихий режим, обязательная причина, статус доставки, аудит, защита от инъекции разметки, запрет внутренних технических данных. Карточка не используется для массовой рассылки.
11. Разделить состояния: приостановка (временный запрет новых запросов, данные и агент сохраняются, возможен срок), блокировка (Telegram, WebApp и фоновые сообщения остановлены, данные и подписка сохраняются), удаление (отдельный процесс: запрос → период ожидания → экспорт → удаление или анонимизация → удаление агента → очистка файлов → аудит).
12. Массовые действия: безопасные — тег, одинаковый грант, служебное уведомление, флаг функции, ограниченный экспорт. Массовая смена подписки, блокировка и удаление — только для высшей роли, с повторным подтверждением, показом числа затронутых пользователей и фоновым заданием с возможностью остановки.
13. Роли и права проверяются на backend, а не скрытием кнопок.

**НЕ ДЕЛАЙ В ЭТОМ ШАГЕ.** Не создавай второй Admin API. Не давай подделывать статус оплаты для ручной выдачи доступа. Не выводи чувствительное содержимое в обзорные списки.

**ТЕСТЫ.** Матрица ролей; поиск по каждому типу идентификатора; фильтры восстанавливаются из адреса страницы; просмотр переписки требует причины и попадает в аудит; ручной override переживает вебхук; массовое действие останавливается; секреты маскированы.

**ГОТОВО, КОГДА.** Оператор решает типовую задачу поддержки полностью из интерфейса, и каждое действие остаётся в аудите.
