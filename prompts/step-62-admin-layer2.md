# Шаг 62. Административные разделы второго слоя

- **Приоритет:** P12
- **Зависит от:** шаги 45–57, 61
- **Feature flag:** EVA_ADMIN_LAYER2
- **Объём:** 1–2 PR
- **Ветка:** `step/62-admin-layer2`

> Перед началом прочитай `CLAUDE.md` — там протокол автономной работы.
> Выполни только этот шаг: проверки, `PROGRESS.md`, pull request, мерж по условиям
> из протокола. Затем возьми следующий шаг порции. На отметке ⏸ остановись.

---

**ЦЕЛЬ.** Дать управление и диагностику всем новым подсистемам. Компонент без административного представления считается незавершённым.

**СДЕЛАЙ.**
1. Реестр методик и версий: локали, статус прав, приложенные подтверждения, схема подсчёта только для чтения, публикация и вывод из обращения, включение по тарифам, шаблоны интерпретаций, агрегированная статистика завершения.
2. Программы, практики и ритуалы: версии, включение, статистика прохождения.
3. Кризисные правила: просмотр и версии, без возможности отключить протокол.
4. Очереди и задания второго слоя, ошибки распознавания и синтеза речи, версии живого портрета, контекстные подсказки.
5. Политики хранения новых классов данных подключаются к механизму шага 10.
6. Массовый просмотр ответов на тесты недоступен без отдельной роли, указания основания и записи в аудит.
7. Настройки ИИ: основной провайдер, базовый URL, ссылка на ключ, модель, до пяти резервных конфигураций, приоритет и условия переключения, health check, таймауты, повторы, размыкатель, незаметное для пользователя переключение, журнал причины переключения. Секреты в браузер и логи не попадают.
8. Общая переработка интерфейса: карточки и строки сервисов раскрываются по нажатию, кнопка ошибок показывает конкретные ошибки, параметры сервера объединены в компактную строку состояния, основной индикатор зелёный при норме и с названием конкретного сервиса при сбое, внутренние сервисы открываются и проверяются, внешние интеграции редактируются и проверяются, каждое действие показывает состояние загрузки, результат и идентификатор корреляции при ошибке.

**НЕ ДЕЛАЙ В ЭТОМ ШАГЕ.** Не добавляй произвольное выполнение кода из интерфейса. Не показывай сырые ответы без роли и основания.

**ТЕСТЫ.** Заблокированная методика показывает причину; публикация версии требует подтверждённых прав; переключение резервного провайдера фиксируется в журнале; мобильная версия админки проходит device-матрицу шага 26.

**ГОТОВО, КОГДА.** Каждая новая подсистема управляется и диагностируется из админки.
